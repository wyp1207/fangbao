# 请评审"按设备分页面"的信息架构设计

## 背景
一套巡检平台，结构是：场站 → 设备（机器人）→ 设备上的外设（相机、传感器、云台）。
现在的实现是"全局"的：环境数据面板、视频面板都从全局表取，切换设备后显示的仍是同一批设备的数据——这是错的。

## 真实差异（现场事实）
- 场站"实验室"有两台设备：
  - 绝影 X30 Pro（四足）：海康 PTZ（可见光 CH101 + 热红外 CH201 双通道）、SF6 气体传感器、温湿度传感器；可以起立/趴下/导航
  - JCROB-01（轮式）：大华 PTZ（另一组通道）、噪声传感器、气体传感器；不能起立，但能导航
- 两台设备的传感器集合、相机通道、可控动作都不一样，不能共用一个页面。

## 目标
每个设备一个页面，页面上的面板由"这台设备有什么"决定：
- 相机面板：按该设备的通道生成（可见光/热红外各一个）
- 环境面板：按该设备的传感器生成
- 控制面板：按该设备支持的动作生成（起立/趴下/导航/云台）

## 请回答（产品 + 后端架构各一段）
1. 数据模型怎么定最省事：`sensor.robot_id` / `video_source.robot_id` 直接绑设备，还是引入 "设备能力/外设清单" 中间表？两者的代价差多少？
2. 页面是"动态渲染面板"还是"按设备类型用不同模板"？哪个更好维护？
3. 切换设备时前端应该重新拉哪些数据？如何避免闪烁和串台？
4. 旧数据（没有 robot_id 的历史传感器/相机）怎么迁移最稳？
5. 如果 12 月要交付，最小可行方案是什么？哪些可以二期？

要求：给具体字段/接口/组件建议，不要泛泛而谈。不确定写"不确定"。
