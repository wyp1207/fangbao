# 测试与自检

改完代码按这个顺序跑，前两步很快，第三步要起服务。

## 1. 后端（50+ 用例，约 5 秒）

```bash
cd server
python -m pytest -q
```

覆盖：登录锁定、CSRF、设备台账、告警闭环（确认/处置/关闭/升级）、
环境传感器阈值、录像与保留、通知通道与外发、设置、用户角色边界、
报表、任务模板、任务执行（回传幂等）、**迁移与模型一致性**。

迁移一致性那条（`tests/test_migrations.py`）值得单独说：
它用 alembic 从零建库，再逐表比对 ORM 模型。开发时手改 sqlite 忘了写迁移，
本地永远发现不了，到客户机器上全新 MySQL 才炸——这条测试就是拦这个的。

## 2. 前端单元测试（17 用例，约 3 秒）

```bash
cd web
npm run test
```

覆盖：

| 文件 | 测什么 |
|---|---|
| `tests/api-client.spec.ts` | 双提交 CSRF、FormData 不设 Content-Type、错误码映射、204 |
| `tests/nav.spec.ts` | 菜单 8 组、子项唯一、中文标签 |
| `tests/auth-store.spec.ts` | 角色权限矩阵（admin/safety/operator/viewer）、改密标记 |
| `tests/force-password.spec.ts` | 强制改密遮罩：不可关闭、规则校验、成功后消失 |

## 3. 端到端冒烟（24 个路由 + 2 个交互，约 2 分钟）

先起服务，再跑：

```bash
# 本机开发
cd web
npm run test:e2e

# 跑部署好的环境
BASE_URL=http://192.168.8.40:8099 E2E_PASS='你的密码' npm run test:e2e
```

每个路由都要求：

1. 页面无 `pageerror`（组件崩溃）
2. 正文不是空白（长度 > 60）
3. 该页特征元素存在（如设置页 `.set-grid`、告警页 `table.grid`）

**这条测试拦的是什么**：之前 `History.vue` 有个 TDZ 崩溃，整站白屏，
单元测试一点感觉都没有——只有真的打开页面才会暴露。

> 注意：强制改密的账号会被遮罩挡住，跑 e2e 要用**已改过密码**的账号，
> 或通过 `E2E_USER` / `E2E_PASS` 环境变量指定。

## 4. 部署后自检（8.40 上）

```bash
cd deploy
bash drill_restore.sh          # 备份→删库→恢复→校验（会真删库，只在可丢弃时跑）
curl -s http://127.0.0.1:8099/health
```
