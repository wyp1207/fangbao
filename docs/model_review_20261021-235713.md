## 豆包 Ark（doubao-seed-evolving）

# 20 个尖锐问题：JCROB 平台放生产会出什么事

```
Q1｜单 uvicorn 进程扛所有事——容器一重启，正在进行的轮询、告警、录像任务谁来续命？
- 谁会问：领导 / 运维
- 现在的答案：单 worker，后台轮询/队列全在进程内；Docker Compose 可自动拉起，但重启窗口内遥测停采、告警推导中断，进行中的内存态任务直接丢，没有任何进程外协调机制
- 放生产的后果：重启 30 秒内机器人真离线了也没人报；重启后告警状态机可能卡在"处置中"无法流转，现场只能改库；更致命的是没人知道这 30 秒发生过什么
- 危险等级：高
```

```
Q2｜MySQL 挂了或者宿主机磁盘写满，平台是降级可用还是整站白屏？
- 谁会问：运维 / 安全
- 现在的答案：没有。用户、设置、告警、台账、审计全落 MySQL/SQLite，没有读写分离、没有降级缓存；磁盘保护只覆盖录像目录，不保护数据库盘
- 放生产的后果：化工区凌晨 DB 盘写满，登录、大屏、告警闭环全部 500；SQLite 场景更糟，写满时库文件可能损坏，恢复要靠备份——而备份演练过没有见 Q19
- 危险等级：高
```

```
Q3｜遥测 10 秒一采、录像按时间分段、告警按规则推导，三份数据时间基准对不齐时，"一键回看该时刻录像"看到的是不是事故现场？
- 谁会问：安全 / 领导
- 现在的答案：没有统一时钟同步说明，也没有对齐精度指标；告警时刻、采样时刻、go2rtc/ffmpeg 切片时刻分别来自不同时钟源和缓冲
- 放生产的后果：事后追责调录像，告警 14:03:10 点开却是 14:02:50 的空画面，关键 20 秒缺失；安监/环保事故复盘时证据链不闭合，平台数据不被采信，责任反落到"平台误报/漏报"上
- 危险等级：高
```

```
Q4｜告警阈值留空=不告警，谁能改、改错了谁负责？三类固定角色能不能管住"传感器标定"这个高危动作？
- 谁会问：安全 / 领导
- 现在的答案：admin/operator/viewer 三类粗粒度角色，传感器阈值是普通 CRUD，没有标定审批/双人复核；留空即静默，没有"应配未配"的强制校验
- 放生产的后果：操作员误把可燃气体阈值删空，该探头永久静默，出事就是重大隐患且审计里只有一条"编辑成功"；等保/安评问"谁授权取消了这个测点保护"，答不上来
- 危险等级：高
```

```
Q5｜告警静默期和去重逻辑会不会把真事故压掉？平台推导的"离线/低电量"误报漏报，责任怎么界定？
- 谁会问：安全 / 运维
- 现在的答案：有静默期和外发抑制，但没有静默期内的强制保底（如持续超限 N 次必发）、没有分级升级；三类平台告警阈值/判定逻辑未说明可配置性
- 放生产的后果：网络抖动引发一批离线告警进入静默，紧接着机器人真在防爆区失联，告警被静默吃掉；或低电量频繁误报导致"狼来了"，运维真忽略时机器人趴窝在管廊中段，夜间拖回风险极高
- 危险等级：高
```

```
Q6｜内网就可以明文裸奔吗——无 TLS、Cookie 属性、CSRF、密码策略、登录防爆破，哪一条过得了等保测评？
- 谁会问：安全 / 领导
- 现在的答案：没有任何安全加固证据。HTTP 明文、无 CSRF token 说明、无密码复杂度/锁定策略描述；虽有审计，但鉴权层本身存疑
- 放生产的后果：等保二级/三级测评直接开不符合项，验收卡住；内网一台办公机中木马即可 CSRF 借用管理员会话改阈值、删告警、关摄像头；化工企业网安抽查时被通报
- 危险等级：高
```

```
Q7｜平台没有任何机器人写操作——真机 11 月 10 日才到、12 月 1 日交付，这 20 天里联调失败算谁的？
- 谁会问：领导 / 开发
- 现在的答案：任务下发/暂停/取消、点位/地图下发、云台控制全缺，等真机+授权；目前所有"打点"只是存草稿，下发链路、协议、授权机制一行没验证
- 放生产的后果：真机协议与预期不符（防爆机器人厂商私有协议极常见），20 天内写操作做不完，验收核心项"远程巡检"不可用；即使砍范围先上线，平台对客户而言只是一块"只读看板"，与预期落差引发合同纠纷
- 危险等级：高
```

```
- 放生产的后果：go2rtc 一崩，首页视频区黑框、回放羊叫，演示时领导正看到这一幕；若 ffmpeg 也从 go2rtc 拉流，事故时段录像直接断档，且黄条告警没有外发，运维不盯着页面根本不知道
- 危险等级：高
```

```
- 危险等级：高
```

**一句话总结：如果明天就上线，最可能出的三个事故是——① 真机协议/写操作在 20 天窗口内联调不完，验收日核心遥控功能不可用，平台沦为只读演示屏；② go2rtc/uvicorn/宿主机任一单点故障或重启，造成告警静默、录像断档、大屏黑框，且无人主动发现；③ 地图参数填错或阈值被误清空而无审批兜底，等真接上写操作后，机器人在防爆区按错误坐标导航撞设备，或该报警的气体泄漏一路静默。**

## 智谱 GLM（glm-5.2）

以下是基于你提供的事实，由甲方技术负责人、产品经理和架构师三个视角融合后提出的 20 个尖锐问题，按“放生产环境爆雷的严重程度”从高到低排序：

Q1｜FastAPI单进程（单uvicorn worker）扛着轮询、队列和Web请求，进程一旦阻塞或崩溃，现场会出现什么情况？
- 谁会问：运维 / 领导
- 现在的答案：单机Docker Compose部署，后台轮询和队列都在单进程内，无多进程容灾。
- 放生产的后果：某一次API请求卡死或内存泄漏导致进程挂掉，全站瞬间瘫痪，机器人变成无头苍蝇，所有告警丢失，如果在夜间无人值守直接引发安全事故。
- 危险等级：高

Q2｜机器人所有的“写操作（任务下发/暂停/云台）”都没做，真机11月10日才到，12月1日交付，这半个月能测透并上线吗？
- 谁会问：领导 / 产品经理
- 现在的答案：写操作全等真机和授权，目前全是只读。
- 放生产的后果：严重延期风险。真机到场后才发现控制协议对接有坑，半个月根本测不完，强行交付会导致现场演示翻车，甚至下发错误指令导致机器人撞毁设备。
- 危险等级：高

Q3｜地图分辨率和原点是“人工填”的，一旦填错一个参数，打点存草稿并下发后会出什么事？
- 谁会问：安全 / 架构师
- 现在的答案：平台地图库靠人工填PNG的分辨率/原点，并与机器人地图名映射。
- 放生产的后果：坐标系完全错位。点位坐标下发后，机器人在厂区里按错误坐标行走，直接撞击管道或反应釜，引发化工爆炸/泄漏，安全问责到底。
- 危险等级：高

Q4｜go2rtc视频服务挂了或摄像头掉线时，首页大屏和告警“一键回看录像”会怎样？
- 谁会问：领导 / 运维
- 现在的答案：首页内嵌go2rtc MSE，告警支持一键回看该时刻录像。
- 放生产的后果：go2rc无状态监控或单点崩溃，首页大屏黑屏导致指挥中心恐慌；发生告警时点回看报404，安全人员无法确认现场状况，无法溯源，被安监局问责。
- 危险等级：高

Q5｜单台机器人轮询间隔10秒，如果机器人在第5秒掉线，平台最快多久能推导出“离线”告警？
- 谁会问：安全 / 架构师
- 现在的答案：每10秒采数据，平台推导电量/急停/离线三类告警，但没写判定逻辑时长。
- 放生产的后果：如果按1次没收到就告警，网络抖动会导致疯狂误报；如果按3次没收到，意味着机器人掉线30~40秒才告警，在化工厂区30秒足够发生严重事故。
- 危险等级：高

Q6｜录像分段MP4、告警时间戳、遥测数据（10秒一次）三份独立数据，时间轴对不齐怎么办？
- 谁会问：开发 / 安全
- 现在的答案：各自独立运行，go2rtc录像、平台记告警、10秒采遥测，无全局时钟同步说明。
- 放生产的后果：发生事故后，告警显示14:00:00，录像跳转却显示13:59:55，遥测曲线在14:00:10，调查事故原因时数据对不上，客户质疑数据造假。
- 危险等级：高

Q7｜告警阈值留空即“未标定不告警”，现场误操作把已标定的阈值清空了，谁来负责？
- 谁会问：安全 / 产品经理
- 现在的答案：环境传感器四档阈值，留空代表未标定，不告警。
- 放生产的后果：操作员手滑或不懂，把有毒气体阈值删空，系统静默，气体泄漏时全厂不报警，这是要坐牢的漏洞。
- 危险等级：高

Q8｜内网部署无TLS，Cookie和CSRF防护怎么做？等保2.0能过吗？
- 谁会问：领导 / 架构师
- 现在的答案：Vue3+FastAPI内网部署，未提及HTTPS、CSRF Token、密码策略。
- 放生产的后果：内网一旦有病毒或内鬼抓包，可直接伪造请求修改设备参数或删除告警记录；等保测评直接不过，项目无法验收。
- 危险等级：高

Q9｜只有用户/角色（admin/operator/viewer），谁能改致命的系统设置和阈值？没有数据审计追溯够吗？
- 谁会问：安全 / 运维
- 现在的答案：系统有14项设置落库即时生效，有操作审计，但权限只有三类粗粒度。
- 放生产的后果：operator误改了系统设置或录像保留策略，导致磁盘写满平台崩溃，或者普通运维人员改了告警外发静默期，导致关键时刻企微不发消息。
- 危险等级：中

Q10｜MySQL/SQLite挂了或者Docker容器重启，内存里的轮询队列和未下发的地图草稿会丢吗？
- 谁会问：运维 / 架构师
- 现在的答案：单机Docker Compose，后台轮询/队列在单进程内，草稿落库。
- 放生产的后果：数据库重启或容器OOM导致进程重启，进行中的任务队列丢失，操作员以为任务还在跑，其实机器人已经停了；或者SQLite并发写锁死直接全站不可用。
- 危险等级：中

Q11｜平台说要扩展到多机器人，现在轮询只盯1台，扩到10台会先崩在哪？
- 谁会问：架构师 / 领导
- 现在的答案：目前多机器人未做，轮询逻辑写死盯1台。
- 放生产的后果：客户二期加车，前端开10个视频流卡死，后端单进程10倍轮询把CPU打满，FastAPI阻塞无法响应Web请求，必须推翻重写多线程/协程调度。
- 危险等级：中

Q12｜没有周报/月报导出，化工厂需要定期向安监局交安全巡检报告，这怎么交付？
- 谁会问：产品经理 / 领导
- 现在的答案：报表正在做，目前只有告警CSV导出。
- 放生产的后果：验收时客户发现无法一键生成合规报表，要求扣尾款；日常运维只能靠人工拼Excel，客户体验极差。
- 危险等级：中

Q13｜告警外发（企微/钉钉）有静默期，如果连续发生不同等级的告警，静默期会不会吃掉致命告警？
- 谁会问：安全 / 产品经理
- 现在的答案：支持静默期，但未说明是全局静默还是按规则/级别静默。
- 放生产的后果：低级别告警触发静默期内，紧接着发生“急停”高级别告警被吞，现场人员没收到通知，延误处置时机。
- 危险等级：中

Q14｜录像保留策略和磁盘保护具体是什么逻辑？磁盘满了是删旧录像还是让平台宕机？
- 谁会问：运维 / 架构师
- 现在的答案：有录像保留策略+磁盘保护，具体阈值未说明。
- 放生产的后果：如果磁盘保护是“只读模式”，满盘后ffmpeg无法写入新录像，go2rtc崩溃；如果是无差别删除，可能把正在作为事故证据的录像删了。
- 危险等级：中

Q15｜设备台账里的TCP/HTTP连通性测试，如果输错IP导致端口扫描，会不会触发厂区工控网络的安全拦截？
- 谁会问：安全 / 架构师
- 现在的答案：提供TCP/HTTP连通性测试工具。
- 放生产的后果：操作员乱填IP测试，被厂区防火墙/工控安全设备判定为非法扫描，封禁平台IP，导致整个巡检系统被踢出生产网。
- 危险等级：中

Q16｜平台推导的“电量/急停/离线”三类告警，和机器人本体上送的告警，如果冲突了以谁为准？
- 谁会问：开发 / 安全
- 现在的答案：目前是平台推导，真机未接入，不知道机器人本体的告警机制。
- 放生产的后果：机器人本体报急停，但平台10秒轮询没收到，平台推导为“离线”，处置策略完全不同（派维修工 vs 派搜寻队）。
- 危险等级：中

Q17｜SLAM 2D地图是只读的，但机器人下次执行任务用的哪张地图，平台能干预或确认吗？
- 谁会问：产品经理 / 运维
- 现在的答案：平台地图库做映射，但机器人写操作（地图下发）没做。
- 放生产的后果：机器人在厂区建了新地图，平台不知道，继续用旧地图映射的点位，下发任务后机器人原地报错或迷路。
- 危险等级：低

Q18｜go2rtc一键注册摄像头，如果摄像头断流又重连，录像文件会不会断层或产生碎片无法播放？
- 谁会问：开发 / 运维
- 现在的答案：ffmpeg录像分段MP4，go2rtc管理流。
- 放生产的后果：网络抖动导致流断开，ffmpeg进程僵死，录像文件损坏。发生事故回看时播放器报错，被客户骂“连个监控都不如海康”。
- 危险等级：低

Q19｜平台没有AI识别和红外测温，遇到机器视觉漏检的隐患，平台怎么兜底？
- 谁会问：领导 / 安全
- 现在的答案：明确没做AI识别、红外测温，全靠人工看视频。
- 放生产的后果：客户验收时发现没有智能分析，认为“这不就是个遥控车加个屏幕吗”，压价或拒收；后期漏检跑冒滴漏被追责。
- 危险等级：低

Q20｜出问题谁能修？日志级别够不够定位？备份恢复演练过没有？
- 谁会问：运维 / 架构师
- 现在的答案：有全站能力异常黄条，但未提及详细日志策略和数据备份。
- 放生产的后果：上线后数据库损坏，发现没有定时备份脚本；出bug时只有默认日志，无法定位是go2rtc还是FastAPI的问题，售后天天飞现场，成本吃光利润。
- 危险等级：低

---

**一句话总结：如果明天就上线，最可能出的三个事故是：**
1. **撞机事故**：人工填错地图分辨率/原点，点位坐标错位下发，机器人直撞化工管道。
2. **监控瞎火**：go2rc单点崩溃或磁盘满导致录像/实时视频全断，发生告警时无画可查。
3. **静默漏报**：单进程卡死或告警阈值被误清空，化工厂气体泄漏/急停时平台毫无反应。
