# UI 设计基线（基于现场实拍参考）

> 参考素材：`D:\Desktop\工作1\机器狗\导览系统效果图\` 下 10 张照片，拍摄于 2025-03-03。没有 Figma，本文件把照片里的布局、色彩、组件和信息架构整理成可落地的 UI 规范。
>
> 注意：照片里是别人已经做好的“智能巡检机器人管理平台”，其中有人脸识别、15 串 BMS、固定设备控制、AI 表计识别等 JCROB 不提供的能力。**视觉可以借鉴，功能不能照搬。**
>
> 最终决定（2026-10-20）：照片**不能原封不动当 UI 使用**，也不能作为图片素材打包进交付物。原因是斜拍屏幕无法无损放大、包含第三方品牌与图标、且大量模块我们没有数据源。正确做法是照它的布局关系、深蓝配色和组件形态，用 Vue + Arco 重写一套组件。

## 0. 参考边界：哪些能参考，哪些必须换

| 类别 | 可以参考 | 必须替换/不能做 |
|---|---|---|
| 布局 | 顶部导航 + 状态条 + 左视频 + 中地图 + 右告警/环境 + 底部消息 | 不要原图当背景；不要固定像素导致 1366×768 错位 |
| 颜色 | 深蓝底、青色高亮、黄色告警、红色故障的配色关系 | 不要照抄对方品牌色值/Logo；我们的 token 见第 3 节 |
| 按钮/面板 | 面板标题、状态按钮、表格操作列、告警弹窗的形态 | 不要复制对方图标、插画、品牌文案 |
| 信息架构 | 巡检管理、监控中心、设备管理、数据查询的层级 | 不要保留 JCROB 不支持的人脸/AI/BMS/固定设备为可点击功能 |
| 交互 | 设备树、可见光/热成像切换、云台控制、告警确认 | 不要做没有死手开关的车体遥控；不要假数据冒充实时数据 |

一句话：**参考它的“骨架和语感”，重画我们的“皮肤和器官”。** 照片是斜拍屏幕，像素级复刻既不可能，也没必要。

## 1. 先说结论：主视觉用哪一张

照片里其实有两种方向：

| 方向 | 代表照片 | 特点 | 建议 |
|---|---|---|---|
| 深蓝高密度控制台 | `IMG_20250303_091616.jpg`、`091643`、`091704`、`091720` | 顶部导航 + 状态条 + 左视频 + 中地图 + 右告警/环境 + 底部消息；信息密度高 | **主方案**，适合 1920×1080 控制室 |
| 深色极简 3D 任务台 | `4e2193ee3c9ec3d378e150933780dd38.jpg` | 左侧图标栏、中间 3D 楼层、右侧今日任务；留白多 | P2 可选，不作为首版依赖 |

首版不要做 3D 数字孪生。JCROB 给的是 2D 栅格地图 + 位姿，先把 2D 地图、视频、任务跑通；3D 模型需要额外建模和坐标配准，6 周内不值得。

## 2. 1920×1080 布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶栏 72px：Logo / 一级导航 / 用户 / 告警铃                     │
├──────────────────────────────────────────────────────────────┤
│ 状态条 40px：场站 设备 电量 在线 重定位 机器人任务 服务器状态   │
├───────────────┬──────────────────────────┬───────────────────┤
│ 左列 360px    │ 中列 1fr                 │ 右列 340px        │
│ 可见光视频     │ 2D 地图（Canvas）         │ 告警统计           │
│ 热成像视频     │ 机器人位姿/轨迹/点位       │ 环境数据           │
│ 云台控制       │ 地图缩放/楼层/图层         │ 巡检点图表         │
├───────────────┴──────────────────────────┴───────────────────┤
│ 底部 220px：巡检消息 / 告警消息 / 控制消息 / 当前任务状态       │
└──────────────────────────────────────────────────────────────┘
```

- 主屏按 1920×1080 设计，最小兼容 1366×768；不做手机端。
- 左列视频固定 16:9，可见光/热成像上下堆叠；热成像可切换到主视图。
- 中列地图必须能显示：地图 PNG、机器人箭头、巡检点、当前路径、目标点、充电桩。
- 右列告警统计用环形图/柱状图；环境数据用紧凑卡片；不要做无意义的 3D 饼图。
- 底部消息区用 tab 切换，默认“巡检消息”；告警弹窗从右下角滑入。

## 3. 颜色与字体

照片是深蓝科技风，但原图饱和度和发光过强。首版建议降一档，保证长时间盯屏不累。

| Token | 值 | 用途 |
|---|---|---|
| `--bg-root` | `#071523` | 页面底色 |
| `--bg-panel` | `#0B2238` | 面板 |
| `--bg-panel-2` | `#0E2C49` | 次级面板/表头 |
| `--border` | `#1D4E74` | 面板边框 |
| `--accent` | `#18B6FF` | 主色/选中/链接 |
| `--accent-2` | `#00E5C3` | 数据高亮 |
| `--success` | `#22C55E` | 正常/在线 |
| `--warning` | `#F5B301` | 告警/注意 |
| `--danger` | `#FF4D4F` | 故障/急停 |
| `--text` | `#DCEEFF` | 主文字 |
| `--text-2` | `#8FB3CE` | 次级文字 |

字体：`Inter` + `Microsoft YaHei`；数字用等宽字体（`JetBrains Mono` / `Consolas`），电量、温度、电压、时间必须等宽，避免跳动。

字号：标题 20–24，面板标题 14–16，正文 12–14，表格 12，状态数字 24–32。

## 4. 组件规范

### 4.1 面板

- 背景 `--bg-panel`，1px `--border`，圆角 4–6px。
- 标题栏左侧 3px 青色竖条 + 标题文字；右上角放“更多/全屏/设置”图标。
- 照片里的斜切角/发光边框可以用 CSS `clip-path` + `box-shadow` 做，但只用于一级面板，表格里不要用。

### 4.2 状态条

必须固定展示：

- 场站、设备选择
- 电量（百分比 + 充电状态）
- 在线/离线
- 重定位状态（成功/失败/进行中）
- 机器人任务（空闲/任务中/充电中/故障）
- 服务器连接状态

颜色规则：在线/成功绿色，充电/任务中蓝色，告警黄色，离线/故障红色。不要只用颜色，必须带文字。

### 4.3 视频卡

- 标题：可见光 / 热成像；右上角显示码流状态、延迟。
- 断流时保留最后一帧 + 半透明遮罩“信号中断”，不要黑屏。
- 热成像右上角显示最高温/最低温/中心温；点击可切换测温规则。
- 视频下方只放必要按钮：抓拍、录像、全屏、云台锁定。

### 4.4 地图

- Leaflet `CRS.Simple` + `imageOverlay`。
- 机器人用带朝向的箭头，不要用圆点；轨迹用渐隐线。
- 巡检点用编号圆点；当前目标点高亮；充电桩单独图标。
- 地图左上角放缩放/复位/图层；右下角显示比例尺和地图名称。
- 坐标换算只做一次：后端返回 `x/y/angle`（米/度），前端按 `origin/resolution` 转像素。

### 4.5 表格

参考照片：深色表头、斑马纹、行高 36–40、操作列固定在右侧。

- 表头允许排序的列带箭头。
- 状态列用“文字 + 色点”，不要只放色块。
- 危险操作（删除、停止任务、充电）必须二次确认，不能只靠图标。
- 分页默认 20 条；导出按钮放右上角。

### 4.6 告警

右下角弹窗参考照片：

- 标题“告警”、等级色条、设备/点位、检测值、阈值、时间。
- 按钮：关闭报警 / 误报 / 详情。
- 同时写入告警列表；弹窗关闭不等于告警已处理。
- 同一点位 30 秒内重复告警只弹一次，列表仍记录。

### 4.7 按钮、输入框与开关

照片里的按钮是“深色底 + 青色描边/填充 + 小圆角”，可以借鉴形态，但要做统一 token：

| 类型 | 样式 | 用途 |
|---|---|---|
| 主按钮 | 青色实底 `#18B6FF`，深色文字，高 32px，圆角 6px | 查询、保存、启动任务 |
| 次按钮 | 透明底 + `#1D4E74` 边框，青色文字 | 重置、取消、返回 |
| 危险按钮 | 红色描边，hover 才实底；只用于停止/删除/急停 | 停止任务、删除点位 |
| 图标按钮 | 28×28，透明底，hover 显示青色背景 | 表格查看/编辑/复制/删除 |
| 开关 | 开启青色、关闭灰色，带文字“开启/禁止” | 云台控制、任务使能 |
| 输入/下拉 | `#071523` 底、1px `#1D4E74`、高 32px | 搜索、设备选择、时间范围 |
| 标签 | 小圆角、半透明底色 | 在线/离线/任务中/充电中 |

规则：

- 同一屏最多一个主按钮；不要把“删除”和“查询”做成同样权重。
- 危险按钮必须带文字，不能只放红色图标。
- 禁用状态用 40% 透明度 + tooltip 说明原因，不要隐藏到用户不知道有这功能。
- 云台/车体控制用“按下才动、松开即停”的按住式按钮或摇杆，不要做成点一下持续动。

## 6. 交互与安全

- 任务下发前做前置检查：`/system/status == Free`、定位成功、地图一致、电量高于阈值、急停未按下、无活动任务。
- 任务启动/暂停/继续/停止都要二次确认；停止按钮永远可见。
- 遥控/云台必须“按下才动、松开即停”；没有死手开关不做车体遥控。
- 任何“未接入”能力按钮置灰，tooltip 说明原因；不要弹“操作成功”假提示。
- 机器人离线/充电/定位失败时，地图上显示最后位姿 + “数据已过期”，不要继续动画。

## 7. 前端实现建议

- Vue 3 + TypeScript + Vite + Arco Design Vue（暗色主题）+ Pinia + Vue Router。
- 颜色用 CSS Variables 覆盖 Arco token；不要每个页面写一套深蓝色。
- 地图用 **Canvas 自绘 + PNG 底图**（`imageOverlay` 式的像素→米换算）；只有未来接地理瓦片时才引 Leaflet。图表 ECharts 暗色主题；视频用 MediaMTX 转 WebRTC，前端优先原生 `<video>`。
- 面板斜切角用 `clip-path`，发光用 `box-shadow`，不要引大体积 UI 框架。
- 图标统一用 Arco 图标；不要混用三套图标库。
- 先做 1920×1080 截图验收，再做 1366×768 适配。
