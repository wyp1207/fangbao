# X30 巡航：原理、与你现在的流程对比、平台怎么接

> 实测环境：192.168.1.106:30000 已通（2026-10-28 17:xx），只做了**只读**探测。
> 结论先给：**手柄设点/保存路径不是协议要求，是控制器上的"示教"功能**。
> 平台可以直接给坐标让它走过去，前提是地图、MapID、初始化定位这三件事对齐。

---

## 1. 你现在的 X30 流程（控制器视角）

| 步骤 | 你做的操作 | 协议层实际发生什么 |
|---|---|---|
| 1 | 用手柄把狗开到场地各处 | 无协议交互（纯遥控） |
| 2 | 远程电脑跑 `start_mapping.sh` 建图 | 导航主机起 SLAM 进程，存 `.pcd/.pgm/.yaml` |
| 3 | 保存地图 | 机器人记录一张地图（控制器里看到"地图1/2…"） |
| 4 | 用手柄控制器设点位、保存路径 | **控制器把坐标存成本体的任务/路径**（这一步是 UI 功能，不是导航必需） |
| 5 | 远程做"初始化定位" | 给定位程序一个初始位姿（对应协议 **2101**，或 ROS `/initialpose`） |
| 6 | 用手柄启动巡航 | 本体按已保存的路径逐个点走（内部还是调 1003 导航） |

**关键点**：第 4 步存下来的"路径"，本质就是"一串 (x, y, yaw)"。
平台不需要那段"预存路径"，它可以自己维护点位、自己逐点发 1003。

---

## 2. 协议层能做什么（我们已实测的字段）

| 指令 | 作用 | 实测/文档 |
|---|---|---|
| **1002** | 读状态：MotionState / Electricity / PosX / PosY / AngleYaw / Location | ✅ 实测：位置 (9.52, -3.66)、电量 100、Location=1、MotionState=0（趴下） |
| **2101** | 重置定位：PosX/PosY/PosZ/Yaw | 文档有，待真机验证 |
| **1003** | 导航到点：Value/MapID/PosX/PosY/PosZ/AngleYaw/PointInfo/Gait/Speed/Manner/ObsMode/NavMode/Terrain/Posture | 文档有，待真机验证（老平台 8890 就是用这个） |
| **1007** | 导航状态：Status（0 完成 / 1 执行 / -1 失败） | ✅ 实测：Status=0 |
| **1004** | 取消导航 | 文档有 |

**注意**：1002 里**没有 MapID 字段**（只有 MapUpdateState），所以平台无法自动知道"机器人当前加载的是哪张图"——
必须在现场用控制器确认，然后告诉平台（我们加了配置项 `JC_X30_MAP_ID`，默认 1）。

## 3. 平台侧巡航需要满足的 5 个条件

| # | 条件 | 现状 | 怎么满足 |
|---|---|---|---|
| 1 | 机器人**起立**（MotionState=2/3），趴下不能导航 | ❌ 当前趴下 | 平台"起立"按钮 / UDP 指令 |
| 2 | 加载了正确地图 | ⚠️ 未知 MapID | 控制器确认 MapID → 配 `JC_X30_MAP_ID` |
| 3 | 做过**初始化定位**，Location=1 | ✅ Location=1 | 平台「重置定位」（2101） |
| 4 | 点位坐标在**这张地图的坐标系**里 | ✅ 已导入真图（402×287，0.1m/px，origin -20.7,-10.7） | 在地图上点选/导入点位 |
| 5 | 目标点在**可通行栅格**上 | ✅ 平台已加栅格校验 | 点墙里会被 409 拦下 |

## 4. 和防爆 JCROB 的区别（为什么 JCROB 早就能巡航）

| | JCROB 轮式（防爆） | X30 四足 |
|---|---|---|
| 下发方式 | HTTP `/task`：**一次下发整条任务**（sub_tasks 含多个导航点+动作） | TCP **1003：一次一个目标点** |
| 谁串任务 | 车端 | **平台**（逐点下发、轮询 1007、判到点、再下一点） |
| 暂停/继续 | 不支持（只能取消） | "暂停"=取消，"继续"=重发目标点 |
| 任务存哪 | 车端 | 本体/控制器有示教路径，但平台可不用它 |
| 平台适配 | `exec_mode=order` | `exec_mode=waypoint`（逐点） |

所以我们平台的巡航代码对两台车是**同一套状态机**，只是执行模式不同——这也是之前留"能力字典"的原因。

## 5. 真机测试计划（不用手柄设点，直接平台下发）

> 安全前提：场地清空、有人值守、机器人急停可用。

| 步 | 动作 | 判据 | 失败怎么办 |
|---|---|---|---|
| 1 | 平台"起立"（或 UDP motion） | 1002 MotionState 变成 2/3 | 检查 UDP 43893 是否通 |
| 2 | 平台「重置定位」：用当前位姿 (9.52,-3.66,0) | Location=1，位姿不变 | 换一个已知点再试（如充电桩位姿） |
| 3 | 单点 goto：当前点 +1m（10.52,-3.66） | 1007 Status 1→0，位姿 x≈10.5 | Status=-1 说明 MapID 或点位不对 |
| 4 | 平台巡航：3 个点位（1m/1.5m/2m 内选） | 逐点走完，平台显示 3/3 | 单点能走、多点不行 → 查逐点间隔 |
| 5 | 取消（1004） | 车停，1007 Status 0/-1 | 现场急停 |

测试用的候选点（已用真实地图栅格校验为"空闲"）：

```
(10.52, -3.66)  东 1.0m
(10.23, -2.95)  东北 1.0m
(11.02, -3.66)  东 1.5m
(10.58, -2.60)  东北 1.5m
```

## 6. 平台还缺的三件事（按顺序）

1. **起立前的地图/MapID 确认向导**（页面提示：请在控制器确认地图编号，填入设置）
2. **巡航前"定位就绪"强校验**（Location=1 才允许下发，已有 located 字段，需要接进 goto/cruise）
3. **地图导入后让用户在图上点选点位**（现在有地图库和点位管理，但点选交互在 2D 页，3D 页只读）

## 8. 真机实测记录（2026-10-28 17:30–17:45）

### 8.1 通了什么

| 动作 | 结果 |
|---|---|
| 只读状态（1002/2001/1007） | ✅ 位姿、电量 95、Location、MotionState 都能读到 |
| 起立（UDP 0x31010202） | ✅ MotionState 0 → 1 → 2（脚本与平台 API 各验一次） |
| 开始运动（0x31010201） | ✅ MotionState 2 → 4（踏步），有延迟需轮询 |
| 前进（0x21010130 = 0.3 归一化） | ✅ 位姿确实变化（约 10cm/s 起步），松手发零速 |
| 停止运动（再次 0x31010201） | ⚠️ 一次没回到站立，需再发/等；记为待优化 |
| 平台 API（/motion-mode、/move） | ✅ 起立→开始运动→前进→停止 全流程走通 |

### 8.2 抓到的真机 P0（已修）

**Location 语义写反**：官方文档 `定位正常=0、定位丢失=1`，我们原来按 `1=正常` 解析。
真机现在 `Location=1`、`/location_status=1`（确实丢失），修复后平台正确显示"定位丢失"并拦截导航。

### 8.3 一个意外收获

1002 的原始返回里带地图元数据：

```
X0=-57.9  Y0=-53  H=1351  Res=0.1
```

也就是说**机器人自己会上报当前地图的原点/高度/分辨率**——平台可以拿它和地图库比对，
以后不用再问"你加载的是哪张图"（MapID 仍需控制器确认，但地图几何能自动校验）。

### 8.4 现在为什么还不能测巡航

真机当前 `Location=1`（定位丢失），位姿在地图外。必须按现场流程：

```

bash /home/ysc/jy_cog/system/scripts/start_nav.sh     # 启导航（含定位）
# RViz 里点 [2D Pose Estimate]，按实际位置和朝向拖箭头
# 成功后 /location_status 变 0，激光点云与栅格地图重合
```

之后平台才能：重置定位 → 单点 goto → 3 点巡航。

## 9. 云台控制（2026-10-29 补充）

### 9.1 先回答：X30 的 SDK 里没有云台

- X30 SDK（1002/1003/1004/1007/2101 + UDP 运动）**只到车体**，没有云台指令
- 现场云台是**海康双光谱相机**（192.168.1.64），走 **ISAPI**：
  - `PUT /ISAPI/PTZCtrl/channels/1/continuous`（pan/tilt/zoom 速度）
  - `PUT /ISAPI/PTZCtrl/channels/1/stop`（这台固件返回 403）
  - 停止正确姿势：`continuous` 全 0（实测 200）
- 老项目 `环境说明/robot-dashboard/backend/hikvision.py` 里就有实现，只是没进平台

### 9.2 平台已接（实测通过）

| 项 | 结果 |
|---|---|
| 设备信息（只读） | ✅ `deviceName=THERMAL CAMERA` |
| 向上 300ms | ✅ elevation 614 → 630（azimuth 不变） |
| 停止 | ✅ continuous 全 0 |
| 首页 UI | ✅ 实时控制 → 云台控制：▲◀停▶▼ + ＋－（变倍） |

配置（系统设置 → 云台）：

```
ptz.enabled   启用云台控制（默认关）
ptz.host      192.168.1.64
ptz.username  admin
ptz.password  （ISAPI Digest 密码，只写不读）
ptz.channel   1
```

### 9.3 交互约定

- 单击 = 150ms 脉冲；按住 = 每 250ms 一帧，松手停
- 每次下发都写审计 `ptz.move`
- 云台未启用时接口返回明确错误，不会静默失败

### 9.4 还没做

- 预置位（ISAPI `/presets`）——现场常用"回到某个机位"，值得补
- 变倍速度分级（现在是固定档）
- 云台与视频画面联动（点击画面某处转向那里，需要像素→PTZ 标定）
