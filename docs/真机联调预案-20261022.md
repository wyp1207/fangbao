# 真机联调预案（JCROB 轮式防爆机器人）

> 目的：11-10 机器人到场，12-01 交付。中间只有 3 周，现场不能"边试边想"。
> 这份预案规定：每天验什么、怎么验、什么算过、不过怎么办、证据怎么留。
> 参考：[VDA5050 订单状态机](https://github.com/VDA5050/VDA5050/blob/main/VDA5050_EN.md)（业界移动机器人任务状态的事实标准）、
> [AGV/AMR 集成检查清单](https://www.smartloadinghub.com/insights/agv-amr/integration-checklist-controls-throughput-warehouse-mobile/)。

## 0. 一句话原则

**先只读、再写、最后才谈自动化。** 任何一天没通过当天的"通过标准"，就不进入下一天，
宁可压缩功能范围，也不要在客户现场留下"能点但不动"的按钮。

## 1. 到场前必须拿到的东西（缺一样就顺延，不硬上）

| # | 物料 | 谁给 | 没有会怎样 |
|---|---|---|---|
| 1 | 机器人 **HTTP 3546 接口文档 + 版本号**（与固件一致） | JCROB | 只能猜字段，第一天全耗在试错 |
| 2 | **WS 3547 协议说明**（有就给，没有先轮询） | JCROB | 推送方案无法验证 |
| 3 | 写操作**授权书/免责确认**（谁授权、允许哪些动作） | 客户 + 我方 | 下发/云台一律不能碰 |
| 4 | 现场网络：机器人 IP、端口、我方服务器到机器人的**双向连通** | 客户 IT | 读都读不到 |
| 5 | 机器人**固件版本、地图文件、点位清单** | JCROB | 地图对不上，点位全废 |
| 6 | 现场**安全负责人**与急停位置确认 | 客户 | 不敢让机器人动 |
| 7 | 现场电表/网络机柜位置、充电桩位置 | 客户 | 部署方案临时改 |

## 2. 三天读通、两天写通、其余时间稳定（按 10 个工作日排）

### D1 只读打通（不写任何东西）

上午：

1. `curl http://<robot>:3546/status`、`/info`、`/pose`、`/galileo`、`/map`、`/system/is_online`
2. 逐条和我们 `server/app/adapters/jcrob/` 的解析比对，**把差异记到 `docs/联调差异记录.md`**
3. 平台侧：设备台账把 IP 改成真机，`mode` 从 `mock` 改 `jcrob_http`，重启

下午：

4. 平台 `/health/deep` 看 `online=true`、`age_s<2`
5. 大屏看电量/位姿/地图是否与机器人本体显示一致（**拍照对比**）
6. 时钟偏差：平台 vs 机器人时间差（我们的 `clock_skew_s` 会报）

**D1 通过标准**：连续 30 分钟 `age_s < 3s`，无一次 `JCROB_UNREACHABLE`；位姿偏差 < 0.5m（目测+地图比对）。

### D2 只读稳定性 + 字段校准

1. 连续跑 8 小时，记录：失败次数、最长中断、内存/CPU
2. 电量、电压、速度、定位状态与实际对照（**抄表**：本体屏幕 vs 平台）
3. 地图：平台显示的地图与机器人 SLAM 图是否同一张；比例尺/原点对不对
4. 断网演练：拔网线 60s，看告警是否只报一条（我们做了抖动→warn、持续→critical）

**D2 通过标准**：8 小时失败 ≤ 3 次且能自恢复；断网 60s 只产生 1 条 warn、恢复后自动恢复（`resolved_at` 有值）。

### D3 写链路第一发：最保守的动作

> 前提：授权书已签、安全负责人在场、场地清空、急停在手边。

1. 先只做**暂停/继续**（不改路线，只改运动状态）
2. 再做**一次只含 1 个点位的任务**：出发 → 到点 → 停 → 回充
3. 全程录屏 + 记录 `task_run` 的每一步时间戳
4. 失败立刻回退：平台侧 `cancel` + 本体急停

**D3 通过标准**：单点任务 3 次连续成功，平台记录与实际动作时间差 < 5s。

### D4 完整路线 + 异常分支

1. 3–5 个点位的完整路线，连续 5 次
2. 异常分支各演一次：
   - 任务中急停 → 平台状态是否正确变成失败/中止
   - 手动挪动机器人 → 定位丢失 → 平台是否报警
   - 断网 → 恢复 → 任务能否续/补录
   - 低电量 → 是否自动回充

**D4 通过标准**：5 次完整路线成功 ≥ 4 次；4 个异常分支的**平台状态与本体状态一致**。

### D5–D7 连续跑 + 指标采集

- 每天 3 条完整路线，连续 3 天，统计：成功率、平均耗时、异常次数
- 同时接入**环境传感器**（气体/烟感/温湿度），验证超限告警 10s 内进告警中心
- 每天收工前导出一次报表 + 审计链校验（`/audit-logs/verify` 必须 `ok=true`）

**D5–D7 通过标准**：3 天累计 ≥ 9 条路线，成功率 ≥ 90%，环境告警端到端可复现。

### D8–D10 交付演示 + 文档

- 按客户验收口径走一遍（模板 → 下发 → 执行 → 暂停/继续/取消 → 回传 → 报表）
- 补：点位同步、地图下发（如果协议支持）
- 交材料：联调差异记录、验收记录（含截图/录屏/日志）、遗留问题清单

## 3. 任务状态映射（照 VDA5050 对齐，别自造状态）

| VDA5050 | 我们的 `task_run.status` | 说明 |
|---|---|---|
| `INITIALIZING` | `planned` | 已下发，机器人未开始 |
| `RUNNING` | `running` | 执行中 |
| `PAUSED` | `running` + `paused_at` | 暂停不改主状态，单独字段 |
| `FINISHED` | `done` | 正常结束 |
| `FAILED` | `failed` | 含动作失败（`RETRIABLE` 也记 failed，带 `retriable` 标记） |
| 人工取消 | `cancelled` | 平台侧取消 |

**为什么照 VDA5050**：客户以后换车（四足/挂轨/别家轮式）时，状态语义不用重讲一遍；
我们现在的 5 个状态已经能一一对上，只需要补 `paused_at` / `retriable` 两个字段。

## 4. 失败回退矩阵（现场决策表，不许临场发挥）

| 现象 | 先查 | 处置 | 何时放弃 |
|---|---|---|---|
| 连不上 3546 | 网络/防火墙/端口 | 换直连网线；客户 IT 开端口 | 2 小时仍不通 → 当天只做本地演示，写差异单 |
| 字段缺/类型不同 | 对比 PDF 与实际 JSON | 适配器加兼容分支（只加不删） | 缺的是写操作必需字段 → 写链路顺延 |
| 时钟偏差 > 5s | 机器人 NTP | 让客户对时；平台侧记录偏差并在报表标注 | 偏差 > 60s → 录像/告警时间不可信，必须解决 |
| 坐标对不上 | 地图比例尺/原点 | 用平台标定功能重标；或改用机器人坐标直显 | 偏差 > 2m → 不允许下发点位 |
| 点位无法同步 | 协议是否支持写点位 | 先只读展示 + 人工在机器人端配点 | 协议不支持 → 改为"平台模板 + 人工点位编号" |
| 任务下发无响应 | 机器人是否收到 | `cancel` + 急停；抓机器人日志 | 连续 2 次无响应 → 停止写测试 |
| 急停后状态不更新 | 机器人上报频率 | 平台侧强制置 failed 并记审计 | 状态长期不一致 → 不允许无人值守 |
| 断网后数据缺口 | 机器人是否缓存 | 用 `/task-runs/ingest` 补录（API Key） | 无缓存能力 → 合同写明"断网期间数据不补" |

## 5. 安全红线（写进现场纪律，违反即停）

1. **没有授权书，不碰任何写接口**（下发/暂停/云台/回充）
2. 写测试时**必须有安全负责人在场**，急停在 1 秒可达范围
3. 首次写测试**限速**（按本体最低档），场地清空，人员离机器人 ≥ 3m
4. 平台侧必须有 **watchdog**：下发后 30s 无状态变化自动告警并尝试 cancel
5. 任何异常**先急停、再排查**，不允许"再看看"
6. 所有写操作进审计（已有），现场每天导出一次

## 6. 证据怎么留（验收/纠纷时全靠这个）

| 证据 | 形式 | 存放 |
|---|---|---|
| 接口原始报文 | `curl` 输出 + 时间戳 | `docs/联调证据/D1/` 等 |
| 平台侧状态 | `/robots/{id}/status` 采样（每 10s 一次，脚本） | 同上 |
| 一致性对比 | 本体屏幕 vs 平台截图（同一时刻） | 同上 |
| 任务执行 | `task_run` 的 JSON + 每一步时间戳 | 导出 JSON |
| 审计链 | `/audit-logs/verify` 返回 | 每天一份 |
| 异常 | 录屏 + 机器人日志 + 平台日志 | 按事件建目录 |

## 7. 这 3 周里**不依赖真机**、可以并行做完的

真机没到不等于只能等。下面这些现在就能做，且能降低 D1–D4 的风险：

| # | 事情 | 为什么现在做 |
|---|---|---|
| 1 | **写链路骨架**（状态机/审计/幂等/权限/watchdog/回退 UI），用 mock 适配器跑通 | 真机协议一确认只填 HTTP 调用，不用重写业务 |
| 2 | **环境传感器接入**（Modbus/MQTT 网关 + 模拟器 + 阈值台架） | 化工场景命门，和机器人无关 |
| 3 | **手机端拍照/扫码**（浏览器 camera API） | 人工巡检闭环缺的证据链 |
| 4 | **等保三权分立** | 纯权限设计，越晚改越贵 |
| 5 | **考核报表（按人/班组完成率）** | 数据已有，只差聚合 |
| 6 | **5 台 mock 并发压测 + 录像容量测试** | 提前暴露性能问题 |
| 7 | **GB28181/ONVIF 批量接入** | 存量摄像头复用是客户最认的降本点 |

## 8. 交付判定（12-01 拿什么去验收）

必须全部满足：

- [ ] 真机 20 次任务连续成功（或 ≥ 90% 且失败可解释）
- [ ] 暂停/继续/取消 三个动作各验证 ≥ 3 次
- [ ] 环境传感器 ≥ 3 类接入，超限 10s 内告警
- [ ] 告警外发真实通道打通，失败可重试、可升级
- [ ] 报表标注实际数据覆盖，审计链 `verify=ok`
- [ ] 遗留问题清单签字（哪些二期、哪些不做、为什么）

不满足任一项 → **谈范围或谈日期，不硬交**。
