# 请给「实时消息」模块做交互与功能设计（已有初版代码）

## 现状
首页一个模块：左边 tab（巡检消息/告警消息/控制消息）+ 两列表格（时间/内容），右边「今日任务状态」。
后端新增 `GET /api/v1/dashboard/feed?kind=patrol|alarm|control&limit=30`，返回：
{items:[{id, ts, text, level(critical|warn|info), badge(未确认/正常/异常), link}]}
- alarm → /alarms?focus=<id>
- patrol → /task-runs?focus=<runId>
- control → /oplog?focus=<opId>

## 问题
1. 表格只有时间/内容两列，信息量低；用户想点进去看详情。
2. 三个 tab 的语义边界不清：巡检消息 = 任务执行结果？控制消息 = 谁下发了什么？
3. 没有未读/新消息提示，靠定时刷新。
4. 当前列表不可滚（已改 overflow），但没分页/加载更多。
5. 没有按设备过滤——多设备时消息混在一起。

## 请给
1. 三个 tab 的准确定义（各自数据源、字段、排序、去重）
2. 表格列设计（列名/宽度/省略策略），click 之后的落点（页面 + 高亮方式）
3. 未读/新消息怎么提示最省事（不引入 WebSocket）
4. 分页 vs 加载更多 vs 固定 30 条，选哪个，为什么
5. 按设备过滤放哪里（顶部筛选 / 跟随当前设备），会不会和"今日任务状态"冲突
6. 空状态/错误态/加载态文案
7. 最小可行改动清单（按投入产出排序，每条 1-2 句）

要求：具体到字段和组件，不要泛泛而谈；不确定写"不确定"。
