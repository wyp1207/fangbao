# 请评审"场站-设备-外设-能力"的数据模型与模块联动逻辑

## 现场事实
同一场站内的设备配置可能完全不同：
- 绝影 X30 Pro（四足）：海康云台（可见光 CH101 + 热红外 CH201）、SF6 气体传感器、温湿度；能起立/趴下/导航
- JCROB-01（轮式）：大华云台（不同通道）、噪声传感器、可燃气体；不能起立，能导航
- 未来还可能有：轨道机器人、挂载不同的气体/粉尘/声学传感器

## 现状（已实现，但不够）
- `robot` 表：id/name/station/adapter/ip/capabilities_json(JSON: actions/video/env)
- `sensor` 表：有 robot_id（多对一）
- `video_source` 表：有 robot_id（多对一）
- `sensor_gateway`：采集网关，绑定到 sensor
- 首页：按当前设备的 sensor/video 渲染面板，class 里写死了"可见光/热红外"两种面板

## 问题
1. 面板类型写死（可见光/热红外），换成大华的双光云台或三通道云台就不好扩展
2. capabilities_json 是手填的，和外设实际配置可能不一致
3. 场站切换、设备切换、面板渲染三者耦合在一个页面里
4. 告警/工单/任务/录像/报表之间的联动没有成文定义

2. 参考开源做法：Home Assistant 的 device/entity registry、AAS（资产管理员外壳）的 submodel、ThingsBoard 的 device profile，哪一套最适合我们这种 1-20 台设备的私有化场景？为什么？
3. 面板注册表：前端如何做到"有什么外设就渲染什么面板"，且新增一种外设（比如粉尘仪）不用改主页面？给出注册表结构示例。
