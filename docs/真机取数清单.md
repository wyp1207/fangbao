# 真机取数清单

> 2026-10-20 · v1.0 · 对应 PDF：`API接口导航2024_HTTP_20240619142112(1).pdf`（109 页）
>
> **一句话**：真机 2026-11-10 可直连。在那之前，平台按 PDF 把“大体”做完；连上之后，按这张表把“只有真机能给的”取回来。

> 这份文档回答三个问题：**取什么、从哪个接口取、取回来解锁什么**。它不是接口手册（手册是 PDF），也不是现场填报表（那是 `真机联调数据采集表.xlsx`）。

## 0. 怎么用这份文档

| 角色 | 用法 |
|---|---|
| 现场操作的人 | 按第 3 节的分域表格逐条打勾，按第 4 节的节奏跑，按第 2 节的目录交回 |
| 写代码的人（我/Codex） | 第 6 节告诉你每个数据项解锁哪个实现决策；第 7 节告诉你哪些不用等 |
| 验收的人 | 第 8 节是“取数完成”的判定标准 |

三条原则：

1. **能只读就不写**：`GET` 一律优先；写操作只有采集表 01 表签字授权后才做。
2. **原始优先**：不要总结、不要转述，接口返回什么就存什么（探针已自动脱敏）。
3. **可重放**：每次采集带时间戳、固件版本、请求 URL、HTTP 状态，任何时候能复现同一份结果。

## 1. 交付形式：一个取数包，不是一堆截图

```
真机取数包_20261110/
├── 00_元信息.md              采集人/时间/固件/IP/网段/授权范围/安全员
├── 01_http/                  探针输出的原始 JSON（每接口一个文件）
├── 02_map/                   地图 PNG + 元信息（每张图一份 meta）
├── 03_points/                nav_points / path / point_connections 原文
├── 04_task/                  task / action / 状态跳变时间线
├── 05_ws/                    WS 原始样本（jsonl）+ ping 行为记录
├── 06_network/               时延、断线表现、callback 原文
└── 07_问题记录.md            与 PDF 不一致的地方，逐条带请求和响应
```

命名与元信息规范：

> 探针原始输出是 `<out>/<时间戳>/` 下的**扁平目录**（`system_info.json`、`map_xxx.png`…）。归档时按下面的结构整理；不想整理就原样保留时间戳目录，另附一份 `00_index.md` 说明每个文件对应哪个 D 编号。

- 每个 JSON 文件的**第一个键**必须是采集元信息：
  ```json
  {"_meta": {"at": "2026-11-10T14:03:11+08:00", "url": "/api/v1/system/info",
             "http": 200, "firmware": "6.1.5", "robot": "192.168.x.x"},
   "...": "原始返回"}
  ```
- 地图文件：`map_<地图名>.png` + `map_<地图名>.meta.json`（`resolution / origin / width_px / height_px / md5sum`）；
- 时间线文件：CSV，列固定 `ts,state,progress,current_task,note`；
- 不要放 token、密码、Wi-Fi 密码（探针已经脱敏，手工补的文件也要遵守）。

## 4. 数据回来后，解锁哪些实现决策

| 数据项 | 解锁的决策 |
|---|---|
| D04 `angle_check.json` | 地图箭头用哪个单位、`angle_unit_override` 要不要设、“角度单位待确认”标签能不能撤 |
| D08 + D10 | 坐标换算能不能落地；`h_map` 用 PNG 像素高还是别的 |
| D13 3 点校验 | 换算公式是不是真的对；误差多少可接受（验收第 2 条） |
| D14 + D16 | 点位 CRUD 的读写格式；`name` 为空时 7 字段还是 8 字段 |
| D20/D21/D24 | 进度条显不显示；`current_task` 怎么存；状态机的边界和去抖参数 |
| D26/D29 | WS 是否作为位姿主源；断流判定秒数；ping 格式 |
| D30 | 告警阈值单位（ppm / %LEL / lux），否则告警只能是空壳 |
| D33 | `UNKNOWN` 态多久触发；重连退避曲线 |
| D06 | 能力矩阵里 `supports.*` 哪些能开 |

## 5. 现在（没真机）就能做的 / 必须等的

**现在就能做完（不等真机）：**

- `web/` + `server/` + `contracts/` + `deploy/` 骨架、Docker Compose（8099 / `jc-` 前缀 / `/data/jcrob-platform`）；
- 登录、RBAC、审计、CSRF；
- **Adapter 接口层**：按 `平台方案-定稿.md` §5.8 的方法表把每个方法先写成“有签名、有错误模型、有重试策略”，内部调 Mock；
- **Mock 数据源**：直接用 PDF 里的示例 JSON 造 fixture —— p55 的 `map_params`、p61 的 `saved_maps`、p72 的 `nav_points`、p74 的 `point_connections`、p107 的环境字段。**这些是原厂给的样例，不是编的**；
- 驾驶舱 UI（状态条 / 地图 Canvas / 环境卡 / 告警列表），用 Mock 驱动；
- 任务编辑器（扁平 action 数组）+ 状态机骨架（含 `DRAFT`/`UNKNOWN`）；
- 告警引擎（规则表 + 求值循环），阈值留空、显示“未标定”；
- 历史/导出/审计页面；
- 部署脚本与 Nginx 反代（含 `token=`、回调 token 脱敏规则）。

**必须等真机（写代码可以，但结论不能定）：**

| 阻塞项 | 为什么 |
|---|---|
| 坐标换算真值 | 需要真实 `resolution/origin` 和一张真 PNG 的像素尺寸 |
| 角度单位 | PDF 没写，只能实测 |
| 任务状态机边界 | PDF 列了 6 个状态，没列转换条件 |
| `progress` / `current_task` 语义 | PDF 只给了一个 `0` 和 `null` |
| 告警阈值 | 量纲要现场确认 |
| `callback_action` 可达性 | 内网拓扑决定 |
| 能力矩阵 | 固件版本决定哪些接口存在 |

## 6. 取数完成的判定标准

一份取数包算合格，要同时满足：

- [ ] `00_元信息.md` 有固件版本、IP、网段、采集人、时间、授权范围；
- [ ] 每个 JSON 带 `_meta`（时间/URL/HTTP 状态/固件）；
- [ ] 每张地图都有 PNG + meta（`resolution/origin/宽/高/md5` 齐全）；
- [ ] `angle_check.json` 的 `verdict` 不是 `inconclusive`，或已写明为什么判不出；
- [ ] 至少一条完整任务时间线（创建→启动→暂停→继续→停止），采样间隔 ≤1s；
- [ ] 三个 WS topic 各有 ≥30 秒连续样本，附实际频率；
- [ ] `06_network/disconnect.md` 有拔网线 10s/60s/5min 的记录；
- [ ] `07_问题记录.md` 里每条都有：请求原文、HTTP 状态、响应摘要、临时处理；
- [ ] 全包搜索不到 token、密码、Wi-Fi 密码。

## 附录：最容易踩的字段坑

| 坑 | 事实 | 依据 |
|---|---|---|
| `saved_maps` 没有 width/height | 只有 `resolution/origin/md5sum/map_type/levels/slam_type`；像素宽高要自己读 PNG 头 | p61 |
| `origin` 是 3 元数组 | `[x, y, 0.0]`，第三个通常是地图原点朝向（一般 0），别当对象解析 | p55 |
| `nav_points` 说明 8 字段、样例 7 字段 | `name` 为空时被省略；用 `split(maxsplit=7)` 解析 | p72 |
| `path` 与 `nav_points` 不是一种格式 | `path` 是 `x y z` 三字段，**不要共用一个解析器** | p70 |
| `skip_area` 每行 4 个数 | `x1 y1 x2 y2` 构成一个方格 | p77 |
| `virtual_wall` 每行 2 个数 | `x y` 折线点 | p79 |
| `point_connections.points` 用 `(map, path, index)` 定位 | 不是坐标，是三元组 | p74 |
| `self_test` 是 GET | 索引里方法列“—”只是提取没抓到 | p16–17 |
| `is_online` 不是平台在线 | 它问的是机器人能不能上互联网 | p34 |
| `camera_rgb` 是 Hz 不是布尔 | 0 代表没有数据 | p9 |
| `nav_action.theta` 弧度 / `pose.angle` 度 | 两个单位混用是本项目最容易出的 bug | p91 / p59 |
| `busyStatus=true` 时仍收指令 | 但不立即处理，队列语义未定义 | p11 |
| `/task/stop` 不带 id = 取消全部任务 | 主按钮必须带 id | p89 |
