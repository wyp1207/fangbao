## 一句话

一期交付**二维作业管控平台**：实时定位、任务下发、告警闭环。三维场站和可见光/红外视频属于二期可视化层，底层数据接口已预留，接入时不改架构。

| 历史与审计 | 状态与环境曲线、任务记录、CSV 导出、写操作审计日志 |

## 一期不做什么（以及为什么）

| 不做 | 原因 | 什么时候做 |
|---|---|---|
| 三维场站（数字孪生） | 需要三维建模与渲染管线，与机器人接口无关，成本远超本期 | 二期，作为数据之上的"可视化皮肤" |
| 可见光 / 红外视频、云台 | 需要海康云台与视频转流服务，本期硬件未定 | 二期，接口位置已预留 |
| 热成像测温 | 依赖摄像头支持红外测温 + ISAPI | 二期 |
| 电池单体电压（BMS） | 机器人协议只提供电量百分比与总电压，没有单体数据 | 需厂家开放 BMS |
| AI 表计/缺陷识别 | 机器人协议不带识别结果 | 需外部 AI 服务 |
| 软件急停 | 机器人协议没有急停下发接口，只有硬件急停状态可读 | 取决于厂家 |
| 多机器人调度 | 协议里的调度服务器是外部系统，不是车队管理 | 二期 |
| 7×24 录像 | 机器人电池供电 | 不排期 |

## 三条必须说清楚的边界

**1. 平台的"停止"不是安全急停。**
它只做"取消当前任务"。真正的安全急停是车上的硬件按钮（平台能读到它被按下，但按不了）。失联时平台不具备远程停车能力，车端自治停车由机器人厂家保证——这一条会写进 UI 和操作手册，不做模糊表述。

**2. 位置精度取决于机器人的定位，不取决于平台。**
平台不做 SLAM，显示的位置来自机器人上报。验收按"平台显示位置与现场实际位置偏差"衡量，不用"看起来一致"这种说法。

**3. 未接入的能力会明确显示"未接入"，不会显示 0 或假数据。**
没有 BMS 就不显示单体电压曲线，没有视频就不放黑屏占位。宁可少一个模块，不放一个假的。

## 验证窗口与已知风险（建议在开工时书面确认）

**接口依据**：一期所有机器人接口、字段与能力，均以厂方提供的协议文档（JCROB HTTP/WS，109 页）为依据；文档没写明或自相矛盾的地方（比如某个角度字段的单位、token 有效期），平台一律按“实测确认后再定性”处理，不猜、不写死。

**真机验证窗口**：机器人 **2026-11-10** 起可直连，交付日 **2026-12-01**，中间约三周是真机适配期。

**已知风险**：文档与实机可能存在差异（字段、单位、状态机边界、回调可达性）。对应安排：

1. 11/10 当天先做半天只读冒烟，把风险前置暴露；
2. 差异逐条记录，带请求原文与响应摘要；
3. 若某项差异影响范围，按“换范围不换日期”协商，不在最后一周临时加需求。

这一条写在这里，是把“文档可能有出入”从单方面的隐含假设，变成双方共同确认的前提。

## 二期可以期待什么（不做承诺，只讲顺序）

1. 可见光 + 红外视频接入（云台控制、抓拍、事件片段）；
2. 三维场站可视化（在一期数据之上做渲染层，不动底层）；
3. AI 表计与缺陷识别（对接外部识别服务，结果回平台做人工确认）；
4. 多机器人调度（需厂家调度服务器配合）。

## 验收口径（对外的量化版）

| 项 | 口径 |
|---|---|
| 首屏 | 登录后立即看到最新状态，页面显示数据时间戳 |
| 定位 | 现场 3 个已知点，平台显示位置与实际位置偏差可量化并留档 |
| 任务 | 3 点巡检任务可下发、可暂停/继续/停止，状态与机器人一致，不出现假"执行中" |
| 告警 | 环境超限、急停、离线、任务错误可产生告警；可确认、可查历史、可导出 |
| 失联 | 拔网线后页面在约定时间内标"通信中断"，恢复后自动重连 |
| 审计 | 每个写操作可追溯到人、时间、参数、结果 |

## 演示边界（内部掌握，不印在对外材料上）

- 不演"取消全部任务"（危险操作）；
- 不演没有在真机上连续成功 20 次的功能；
- 首次下发运动指令前，现场负责人须在采集表 01 表第 15–17 行签字；
- 备一条 5 分钟录屏，网络或机器人异常时放录屏。
