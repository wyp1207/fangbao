# B. 产品经理视角

## A1. 观众是谁，一定会问的三个问题

12/01 的观众大概率三类，且**拍板的不是运维**：分管领导（看“像不像、安不安全、能不能交差”）、安全/生产部门（看“机器人能不能替人、出事谁负责”）、信息/数字化部门（看“接没接进来、数据真不真、以后怎么扩展”）。【判断】

**一定会被问到的三个问题：**

1. **「现场出事（泄漏/火情/人员闯入），这个平台怎么告诉我？」**
   他们不关心阈值引擎，关心的是：告警弹不弹窗、几秒到、谁确认、怎么闭环。你本期只有阈值推导告警，没有 AI 识别、没有视频复核，答案会显得单薄。【判断】
2. **「这机器人现在在哪、电够不够、能不能马上让它去看一下 XX 点？」**
   即“地图上点一下 → 机器人去”。这是演示的高潮动作，必须一次成功。【判断】
3. **「这个东西和之前 PPT 上那个三维场站是不是一个？为什么没有画面/没有 3D？」**
   参考图已经流出去过，这个问题 100% 会被问，不能现场支吾。【判断】

**必须现在改**：把这三个问题的标准答案写成演示话术，尤其第 3 条，要主动讲“一期打牢数据与控制底座、二期叠加三维与视频”，不要等被问。【判断】

## A2. 3D 落差如何管理；低成本补“平台感”的具体手段

**【判断】落差管理的核心：不要试图用 2D 假装 3D，要把“实时、可控、数据真”做出质感。** 参考图给人的冲击来自三点：空间沉浸感、告警气泡密度、多面板信息密度。前一点无法低成本追，后两点 2D 完全能追平甚至超越（因为你有真数据，PPT 是假的）。

**组件级手段（按性价比排序）：**

1. **场站底图做“卫星图/平面图彩化 + 区域分区着色”**：生产区/管廊/装置区用不同半透明底色，道路、围墙、建筑轮廓描边。一张处理过的 PNG 底图（Figma/QGIS 半天工作量）观感提升远大于任何前端特效。**必须现在做**，不要直接铺机器人导出的原始栅格地图（灰白像素格看起来像调试工具）。【判断】
2. **顶部全局 KPI 状态条**：在线状态点（绿/灰呼吸灯）、电量数字+电池图标、急停红色徽标、当前任务、延迟毫秒数。参考图顶部没有，但这是“平台感”最便宜的来源。【判断】
3. **告警用与参考图同款的 WARNING 黄黑气泡**，锚定在点位坐标上，带呼吸光晕与聚合（同点多告警折叠成 `×3`）。200 点位里有 5–8 个告警气泡时，视觉密度立刻接近参考图。【判断】
4. **机器人位姿用带方向的箭头/小车图标 + 轨迹尾迹（最近 N 点渐隐）**，配合 1s 实时移动，这是 2D 图上唯一“活”的元素，一定要流畅。【判断】
5. **深色科技风主题**（深蓝/黑底 + 青色描边 + 告警黄）。参考图是浅底 3D，但领导对“工业平台”的审美预期普遍是深色大屏；Arco 深色主题 + 自定义 CSS 变量成本很低。**注意**：日常操作用浅色，演示大屏用深色，做两套主题，不要二选一。【判断】
6. **左右信息面板常驻、可折叠**，布局直接抄参考图：左侧可见光/红外占位，右侧机器人状态仪表 + 历史告警流。即使内容是占位，骨架在就“像一个平台”。【判断】

**不要做的事**：不要上 Three.js 建简模、不要做假的 3D 管道——六周单人做出来的 3D 只会更廉价，且抢走关键路径时间。【判断】

**过度设计判定**：2D 地图上做设备的悬浮立牌/伪 3D 图标（billboard）可以，真正的三维场景砍了，失去的是“给外行看的第一眼震撼”，换来的是六周能交付。【判断】

## A3. 本期不做的东西在 UI 上如何呈现

1. **“占位 + 二期标识”（推荐用于视频/红外面板）**：保留参考图的双画面面板位置，显示摄像机轮廓图标 + 「视频通道（二期）」标签。好处是布局完整、客户能看见规划；坏处是会被问“什么时候有”。**必须**配话术与二期路线，不要只写“敬请期待”，那像半成品。【判断】

# C. 全栈工程师视角

## B1. 单进程 asyncio + 单 worker 的风险与拆分触发条件

**风险点：**
- 所有协程共享一个事件循环，**任何一处同步阻塞（pymysql 误用、大结果集序列化、Pydantic 校验超大 JSON、Excel 导出）会让 1s 轮询和 WS 心跳一起停**；WS 每秒 ping 停了直接断连。【事实+判断】
- 进程重启 = WS 断连 + 状态缓存全丢，重启窗口内任务对账空窗。【判断】
- 后台任务与 HTTP 请求竞争同一循环，导出大报表时页面卡顿。【判断】

**纪律（现在就要定）**：全程 `async` 驱动（SQLAlchemy async、`httpx.AsyncClient`）；禁止 `requests`、同步 `openpyxl` 之类进请求路径，导出走 StreamingResponse 或离线生成文件；CPU 重活用 `run_in_executor`。【判断】

**必须拆分的触发条件（达到任一）：**
1. 第二台机器人接入——立刻把 poller/ws_listener 拆成独立进程（加 Redis/Stream），这是架构红线，不要试图单进程扛多机。【判断】
2. p95 HTTP 响应 > 500ms 且 profiler 显示后台循环占用 > 30%；【判断】
3. 状态入库持续追不上采集（积压 > 10s）；【判断】
4. 日活/并发用户 > 20 同时在线，或 uvicorn 单 worker CPU 持续 > 70%；【判断】
5. 需要 7×24 不中断重启（本项目机器人不 7×24 运行，此条暂不适用）。【事实】

在这些条件之前拆，是过度设计——一台轮式机器人、内网几十个用户，单 worker 绑单核都用不满。【判断】

## B2. HTTP 1s 轮询 + WS 双源一致性

**【判断】位姿以 WS `/galileo/status` 为准（`currentPosX/Y/currentAngle/currentSpeedX`），HTTP `/navigation/pose` 仅在 WS 断连时兜底。** 理由：WS 推送频率和实时性更好，且 galileo_status 同时带速度/目标/状态，是自洽的一组；混用两个源的位姿会出现箭头跳变。

**时间戳对齐：**
- 每条样本落库/进缓存都带 `source_ts`（接口给的时间就用，不给就用本地接收 `recv_ts`）与 `source` 字段；PDF 未明确接口是否带时间，**未验证，W1 冒烟必须确认**。【未验证】
- UI 只认一个「最新状态对象」：WS 更新就整体替换该对象的位姿字段；HTTP 轮询数据（`/system/status`、`/system/info`）合入同一对象的其他字段，**不回写位姿**，避免旧 HTTP 帧覆盖新 WS 帧。【判断】
- 合并规则：按 `recv_ts` 单调，旧帧直接丢弃（你的口径 13「超 3s 变灰」在此实现）。【事实+判断】

**防抖：**
- 地图箭头用 CSS transform/requestAnimationFrame 插值（在两个相邻 WS 位姿间线性补间），不要每帧 setPosition 生硬跳；角度用最短弧插值。【判断】
- 静止判定：速度≈0 且位姿抖动小于阈值（如 0.05m）时冻结图标，否则静止时箭头会“抽搐”——SLAM 静止漂移几乎必然发生。【判断】
- 单位：位姿换算后统一存米和度，`nav_action.theta` 弧度只在出站 DTO 转换；`currentAngle` 单位按口径 5 多帧判定，**但 11/10 前要在 Mock 里留切换开关，别写死**。【事实+判断】

## B3. Canvas 自绘地图的必踩坑

200 点位 + 2000 轨迹点对 Canvas 毫无性能压力（2k 图元是小场面），**真正的坑全在交互正确性**：【判断】

1. **坐标换算是头号 bug 源**：`x=x0+px*res`、`y=y0+h*res-py*res`，PNG 的 `h` 必须以实际解码像素为准（注意 EXIF orientation、2x 图、CSS 缩放与设备像素比 DPR）。**必须**写一个正反变换的单测：随机 100 个点「像素→地图→像素」闭合，误差 < 1px。点位 CRUD、点击拾取全走这一对函数。【事实+判断】
2. **DPR 适配**：canvas 物理尺寸 = CSS 尺寸 × `devicePixelRatio`，否则高分屏模糊；所有鼠标坐标先除以 bounding rect 缩放比再换地图坐标。【判断】
3. **视口变换统一用一个 transform 矩阵**（平移/缩放），绘制和拾取都过它；不要手写三套缩放变量。缩放范围设上下限（如 0.3–8），滚轮以鼠标位置为锚点缩放。【判断】
4. **拖拽编辑与页面滚动手势冲突**：地图容器内 preventDefault，触屏双指缩放要处理。【判断】
5. **性能层面**：底图离屏 Canvas 缓存（缩放后重绘一次即可）；轨迹线用单一 `Path2D` 一次 fill/stroke，不要 2000 次 beginPath；点位 hover 命中检测用包围盒粗筛 + 距离精筛，200 个不需要 R 树（上空间索引是过度设计）。【判断】
6. **虚拟墙/忽略区是多边形编辑**：本期建议只做矩形/多边形顶点的增删，不做边拖拽插入顶点——后者吃掉你三天且客户看不出区别。**这是可砍项**，砍了失去精细区域绘制，保留矩形覆盖 80% 场景。【判断】
7. **地图 MD5 变化**：机器人换图后 PNG 变了但 name 没变怎么办？`saved_maps` 给了 md5，前端按 md5 缓存底图，变化强制刷新并清空该图上的点位缓存（**点位是平台资产，不能级联删除**，只解绑/标记待迁移）。【事实+判断】
8. 轨迹 2000 点直接连折线会“穿墙”（采样稀疏处），演示效果反而误导；**只画实际走过的尾迹，不做路径推算**，并标注这是实际轨迹。【判断】

## B4. 任务状态机、2s 对账在丢包/超时/重启下的坏法与幂等

**会怎么坏：**

1. **下发成功响应丢失（超时）**：平台以为没下发，用户再点一次 → 机器人收到两个任务。你的口径 11「不自动重试」是对的，但**人工二次点击同样会重复**。需要幂等键兜底。【判断】
2. **任务在机器人端 COMPLETE，但对账轮询时机器人重启**：平台长时间停在 WORKING；机器人起来后 `/task` 列表是否保留？**PDF 未保证，未验证**——W1 必须实测「机器人重启后任务列表与状态」。若任务消失，平台会把 WORKING 置成什么？建议终态：`UNKNOWN(机器人重启中断)`，**不要自作主张标 COMPLETE 或 CANCELLED**。【未验证+判断】
3. **`stop` 超时但实际生效**：机器人已停，平台显示“停止失败”，操作员再点；因 stop 无 id 会取消全部——风险叠加。这是必须后端封死的接口（见结论 5）。【事实】
4. **PAUSED 期间机器人端被人工/第三方 resume**：对账发现状态不符，平台是跟随还是拉回？原则既然是“机器人是唯一真相源”，**一律跟随并在任务时间线写系统事件「外部状态变更」**，不要反向下发纠正（纠正写操作在异常期最危险）。【判断】
5. **状态枚举映射**：`WAITTING/WORKING/PAUSED/CANCELLED/ERROR/COMPLETE`（注意是 WAITTING 原文拼写，你的 DTO 要按原文、别手滑改成 WAITING）。平台状态机只认这 6 态 + 本地 `UNKNOWN`，对账时不在枚举内的原值原样留存并告警，不做猜测解析。【事实】

## B8. 安全设计在内网是否过度；哪里不够

**【判断】JWT(httpOnly) + CSRF 不过度——它们几乎是默认配置成本，砍了只省半天，留着防的是“内网横向 + 将来上公网不用重构”。但有两处可简化：**

- 单进程、Cookie+同源前端的部署下，CSRF 用双重提交或 SameSite=Lax/Strict 即可，不必上完整 token 库；【判断】
- 基础 RBAC 本期角色建议**只做两级：管理员/操作员 + 查看者**，不要做资源级权限矩阵——那是过度设计，砍了失去细粒度分权，六周内零收益（审计日志 + 签字授权已经覆盖责任链）。【判断】

**不够的地方（按真实风险排序）：**

1. **机器 token 落库“加密”要想清楚威胁模型**：平台要拿它原文调接口，所以最多是对称加密（如 Fernet/AES-GCM），密钥放环境变量/挂载文件，**绝不进 git、不进镜像、不进 MySQL 连接串旁边**。比 token 泄露更常见的是：**token 出现在日志/报错里**（URL query、exception traceback、httpx 访问日志）。`GET /token?username=&password=` 意味着机器人账号密码也在 query——日志中间件必须对 query 做脱敏白名单。**必须现在做日志脱敏。**【事实+判断】
2. **回调伪造（你的口径 8，URL 里带 run token）**：HTTP 明文 + URL token 的问题是 token 会进机器人端日志/网关日志；缓解：回调端点只接受「状态回报」类写入且 run token 一次性、短时效（任务生命周期内有效、完成即废）、回报内容只允许把任务标为中间态/完成，**回调永远不能触发新运动指令**；另外校验回调来源 IP 为机器人 IP（内网可做）。这样即使被伪造，后果上限是“谎报完成”，且审计可对比机器人真实状态抓出不一致。**必须现在就把回调权限收窄到只读式回报。**【事实+判断】
3. **JWT 无撤销的问题你有（人+机器人都是长期凭证）**：人员 JWT 设短有效期（如 2–4h）+ 服务端可失效（单进程内存一个撤销集合即可，不上 Redis）；机器人 token 无法控制 TTL，靠 401 重取。【判断】
4. **审计缺“人”**：operation_log 必须记 `who(用户id+登录IP)/when/what(动作+目标)/result/机器人返回摘要`，登录失败、登录、签字授权、写操作全覆盖；签字授权建议落成一条可导出的记录（操作人+负责人+时间+任务范围），这东西在安健环体系里比技术防护更被看重。【判断】
5. **将来上公网**：现在至少做到——密码 bcrypt/argon2、默认管理员密码首次登录强制改、调试接口（如 `/docs`）生产关闭或加开关、nginx 限流与 body size 限制。成本都很低。【判断】
6. HTTP 明文到机器人在内网可接受，但平台到浏览器若客户介意，预留 nginx HTTPS 配置（自签/内部 CA），不做但留好开关。【判断】
