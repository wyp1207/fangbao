### P1-1 告警翻页第 2 页起为空，27 条只看到 10 条

**复现**：登录 → 告警中心 → 告警记录 → 点“下一页”或页码 2。  
**实际**：页码显示“第 2/3 页”，表格 0 行；第 1 页 10 行。  
**接口返回**：`GET /api/v1/alarms?limit=10&offset=10` → `200`，`items` 长度 10，`total=27`。接口有数据，前端自己又切了一次。  
**位置**：`web/src/pages/Alarms.vue:63-64` 已按 `offset` 取数，`:70` 又 `slice((page-1)*10, page*10)`，第二页把服务端返回的 10 条全切掉。  
**严重度**：严重（17/27 条告警在 UI 不可达，直接影响处置）。

### P1-2 首页切换场站后，实时数据仍是上一台设备

**接口返回**：`GET /api/v1/robots/2/status` → `200`，`{"online":false,"age_s":-1.0,...}`；页面却没有使用它。  
**位置**：`Dashboard.vue:118-127` 的 `onSite` 只改 `deviceId` 和 toast，没调用 `robot.setDevice()`；设备下拉的 `onDevice` 才调用。  
**严重度**：严重（监控大屏显示错设备的数据，值班判断会被误导）。

### P1-3 工单、人工巡检、任务执行、任务模板、AI 识别不在菜单里

**复现**：展开全部菜单；或在告警页点“转工单”。  
**实际**：菜单只有“任务管理/巡检点位/任务日历”，没有“人工巡检/工单/任务执行/任务模板/AI 识别”。这些页面手输 URL 均可正常打开。告警转工单成功后 toast 写“去「工单」页派单”，但菜单里没有“工单”。  
**接口返回**：  
- `POST /api/v1/inspection/tasks/generate` → `200`（直接访问 `/inspection` 时可用）  
- `POST /api/v1/task-runs/6/cruise` → `403` `{"code":"WRITE_LOCKED","message":"写操作未开启：需真机联调通过 + 现场授权书，然后在系统设置开启「允许下发任务」"}`  
**位置**：`web/src/config/nav.ts` 未包含 `inspection/work-orders/task-runs/task-templates/ai-results`；`Tasks.vue` 的“新建任务/下发”也不调用 `/task-runs`。  
**严重度**：严重（验收要求里的“生成任务、单点下发、巡航、工单闭环”在正常菜单路径上无法完成）。

### P1-4 桌面工单页不显示“手机链接”

**复现**：打开 `/work-orders` → 看任意工单行。  
**实际**：只有“派给”和“↑”，没有链接、复制按钮或二维码；接口其实返回了手机地址。  
**接口返回**：`GET /api/v1/work-orders` → `200`，工单对象含 `"mobile_url":"/m/wo/4"`。  
**位置**：`WorkOrders.vue` 模板未渲染 `mobile_url`，`assign()` 也未使用分配响应中的 `mobile_url`。  
**严重度**：高（现场人员拿不到手机处理入口，只能靠通知通道外发）。

### P1-5 手机链接登录后丢失目标，回不到工单

**复现**：退出登录/无痕窗口打开 `/m/wo/4` → 被重定向登录 → 用 admin 登录。  
**实际**：落到 `/dashboard`，不会回到 `/m/wo/4`；手机链接在“需要登录”场景下失效。  
**位置**：`Login.vue:19` 固定 `router.push({name:'dashboard'})`；`router/index.ts:68-74` 的守卫也不带 `redirect`。`MobileWorkOrder.vue:79` 虽然写了 `redirect` 参数，但登录页不消费。  
**严重度**：高。

### P1-6 写开关打开后，任务/模板按钮仍会被锁死（“假锁”）

**复现**：查看 `robot.write_enabled` 设置说明与任务页按钮实现；不实际改开关。  
**实际**：任务页“新建任务/下发/暂停/继续/取消当前任务”全部固定打开写锁说明；任务模板“下发”是 `disabled` 硬编码。写锁弹窗却承诺“授权签字后，这些按钮直接可用，页面不用改”。  
**接口返回**：这些按钮根本不发请求；真正会返回 403 的是隐藏页 `/task-runs` 的 dispatch/cruise。  
**位置**：`Tasks.vue:108,136-137,185-188`（`locked = '...'` 无开关判断）；`TaskTemplates.vue:182`（`disabled` 硬编码）；`Dashboard.vue:158-160` 摇杆也是固定 toast。  
**严重度**：高（打开写开关后 UI 仍不可用，和产品提示矛盾）。

### P2-1 首页跨场站设备芯片导致场站/设备不一致

**复现**：首页保持“当前场站=默认场站”，直接点设备条里的“绝影 X30 Pro”（属于实验室）。  
**实际**：当前设备下拉显示“全部”，当前场站仍是“默认场站”；下拉里只有 JCROB-01，无法直接切回该设备，必须先改场站。

**位置**：`onDevice()` 只改 `deviceId`，不更新 `site`；`deviceOptions` 按 `site` 过滤，找不到当前设备时显示“全部”。  
**严重度**：中。

### P2-2 首页每切一次设备就新增 3 个轮询定时器

**实际**：切换前 5 秒 6 次，切换 2 个往返后 5 秒 10 次；越切越多，长时间值班会持续叠加请求。  
**位置**：`Dashboard.vue:138-140` 在 `onDevice` 里 `timers.push(setInterval(...))`，没有清理旧定时器；`onBeforeUnmount` 才统一清。  
**严重度**：中。

### P2-3 热红外没有视频流，却仍有“打开全屏页”，点开是可见光

## 与“成熟巡检平台应有功能”的差距（结合公开资料，不要编）

公开资料里，成熟巡检平台通常不是“若干页面的集合”，而是 **计划 → 任务/排班 → 现场执行 → 异常上报 → 工单整改 → 复核销号 → 统计报表** 的闭环。海康威视 Infovision PIE 的产品页明确写了“计划—执行—整改”闭环、APP/手持终端现场巡检（问题上报、打卡点绑定、离线巡检）、远程巡检（视频/抓图/录像回看）、自动巡检（AI 事件、热成像、机器人）、问题上报→整改→复核→审核、缺陷复核转检修工单，以及按任务/对象/问题三维度的报表和导出打印。浙江政务云的公开巡检功能表还列了巡检计划类型/频次、任务审核/分配/导出、GIS 轨迹、隐患 TOP3/等级占比/闭环率、事件自动生成工单并同步移动端、区域网格、设备扫码、点位路线规划、APP 端。贵州公共资源交易的方案还提到按设备台账/风险/气象/历史问题智能生成巡查方案和路线。([海康 Infovision PIE](https://www.hikvision.com/cn/software-product/Infovision-PIE/)、[浙江政务云巡检功能表](https://zjjcmspublic.oss-cn-hangzhou-zwynet-d01-a.internet.cloud.zj.gov.cn/jcms_files/jcms1/web2760/site/attach/0/77d23e3a04be470385cbcc7c04be6b24.pdf)、[贵州巡查方案文档](https://ggzy.guizhou.gov.cn/hallweb/hall/attach/nosession/download?attachId=8a8bb7d59cf60983019d055c52e44b61)、[S19 巡检 App](https://apps.apple.com/cn/app/s19%E6%B7%AE%E6%A1%90%E5%B7%A1%E6%A3%80/id6743377533))

对照本平台：

| 成熟平台常见能力 | 本平台现状 | 差距 |
|---|---|---|
| 巡检计划管理、按天/周/月排班、任务审核/分配 | 有巡检计划与“生成任务”，但页面不在菜单；任务日历是“未接入”占位 | 计划—排班—审核链路没有形成可操作闭环；任务日历缺失 |
| 移动端现场执行：扫码/打卡、拍照、异常上报、离线 | 有 `/m/task/:id`，支持扫码、拍照、正常/异常/跳过；手机工单支持拍照 | 菜单/工单页无手机入口；登录后丢 redirect；无离线、GPS/蓝牙轨迹；异常上报后的工单入口不清晰 |
| 工单闭环：上报→派单→处置→复核→销号 | 后端和隐藏页 `/work-orders` 的状态机可走通；手机工单可拍照销号 | 工单页不在菜单、无“新建工单”、无手机链接/二维码；告警转工单后无法从菜单进入派单 |
| 告警全生命周期、确认/处置/关闭、升级通知 | 确认/处置/关闭/转工单均可用；有通知通道和投递记录 | 告警分页第 2 页起空白；通知测试/启停未验证；投递失败只记录，没有明显的重试/告警 |
| 报表分析：完成率、问题率、覆盖率、超时率、整改完成率，Excel/PDF | 有基础统计、Excel 导出、打印页 | 只有汇总数字/列表，没有任务完成率、巡检覆盖率、问题率、超时率、整改闭环率等管理指标；PDF 依赖浏览器打印 |
| 自动巡检：AI 事件、热成像、机器人巡检 | 有机器人状态/视频/AI 结果入库；写操作按授权锁住 | AI 结果页不在菜单；热红外全屏按钮指向可见光；自动巡检的“事件→告警→工单”链路在 UI 上不可见 |
| 地图与巡检点/路线规划 | 有 2D 地图、平台地图库、草稿点位 | “去地图打点”落空；没有路线编辑/路径规划；“任务模板”只是点位序列，不能在图上编辑 |
| 多场站/多设备统一监控 | 有设备条和多设备状态 | 切场站不切实时数据；跨场站芯片状态错乱；设备条延迟出现、轮询定时器叠加 |
| 权限与审计 | RBAC（admin/safety/operator/viewer）、操作日志、接口密钥 | 基本具备；用户角色下拉“选中即提交”缺确认，误操作风险较高 |
| 运维与数据保留 | 遥测 7 天、录像 30 天、磁盘阈值、健康面板 | 健康面板有字段缺失；备份/高可用/恢复演练未验证 |

**结论**：平台的“单点功能”覆盖不算少，后端状态机和接口大多真实可用；当前主要短板不是“没有接口”，而是 **入口、状态同步和分页这类基础交互把已有能力挡在了用户面前**。优先修 P1-1 告警分页、P1-2 场站切换、P1-3 菜单入口、P1-4/P1-5 手机链接，再补任务日历与报表管理指标，才能达到“可验收”的闭环体验。
