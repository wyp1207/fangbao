# 模型评审记录 20261028-123800

## 豆包 doubao-seed-evolving

## 结论与执行

1. **选 A，A 先上、B 后补成立。**  
   Vue3 + Three.js：PNG 按 `resolution/origin` 铺地，过滤后的占据栅格拉伸成体块，复用现有点位、机器人、告警、轨迹。B 后期只补 **5–10 个关键 GLB**：储罐、管廊、泵撬、出入口、主体建筑，不做全站复刻。C 三天内集成和二开风险高，D 不满足 3D 大屏诉求。

2. **程序化 3D 最容易翻车的 3 点：**
   - **脏栅格**：人影、动态设备、噪点被拉成锯齿墙；阈值取 `30–60`，做中值/闭运算，删除 `<0.5 m²` 碎块。
   - **2D 缺高度信息**：所有障碍同高会像围墙且堵门；建筑、设备、围栏分高度，门洞不拉伸。
   - **性能和遮挡**：逐格建 Box、Z-fighting、轨迹埋地；静态体块合并，地面抬高 `0.01–0.02m`，相机用 `35°–45°` 俯视。

3. **坐标对齐最易错：**  
   PNG 行坐标翻转，以及把 SLAM 的世界 `y` 当成 Three.js 的高度 `y`。统一换算：

   `col=(x-origin_x)/resolution`  
   `row=H-1-(y-origin_y)/resolution`

   Three 中地面坐标用 `(worldX, 0, worldY)`，高度另用 `y`；GLB 原点放在底座中心并贴地。用机器人原点和两个已知点位校验。

4. **核显 30fps 的 3 条优化：**
   - 占据格降采样到 `0.25–0.5m`，用合并几何体或 `InstancedMesh`，静态场景尽量 1 个 draw call。
   - `setPixelRatio(min(devicePixelRatio, 1.5))`，关闭阴影，贴图不超过 `2048`，只保留 1–2 盏灯。
   - 轨迹/告警用 `BufferGeometry`、Points 或图集，轨迹控制在 `2000–5000` 点，不做每点 CSS3D 标签。

5. **领导说“不像我们场站”时：**  
   “这版是 SLAM 数据驱动的坐标底模，优先保证点位、轨迹、告警实时、精准对齐，三天可演示；外观复原需要关键设备模型。下一步替换储罐、管廊、建筑等少量 GLB，识别度会明显提升。”

6. **只能改一处：**  
   投 **5–10 个关键设备 GLB 并精确落位**，不要精修全部墙体。

**最终路线：A 做三天演示，B 只补关键资产；先保坐标准、帧率稳，再逐步提升外观相似度。**
