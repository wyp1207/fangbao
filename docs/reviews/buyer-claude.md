## 2. 站在甲方角度，最不能接受的 5 个问题

### 问题 1：核心巡检闭环不存在——机器人是 mock，任务下发是 501

**看到的证据：**

- `GET /health` → `"robot_mode": "mock"`。
- `GET /api/v1/robots` → `mode: "mock"`，`last_seen: null`；IP `192.168.1.100:3546` 从演示机 curl 直接连接失败。
- `GET /api/v1/robots/1/status` → 电量恒 78、电压 37.05、`galileo.header.stamp.secs = 1624970817`（**2021-06-29** 的时间戳），`recv_ts` 是进程运行秒数。这不是实时数据，是 PDF 示例 fixture。
- 机器人地图 `GET /api/v1/robots/1/map/png?name=map1` 是 306×324 的规则矩形平面图；源码 `server/app/adapters/jcrob/mock_adapter.py` 的 `_make_png()` 注释写得很直白：“生成一张‘像楼层平面图’的占位底图……画上墙体和房间，大屏才像一张真地图。”**这不是 SLAM 地图。**
- `POST /api/v1/task-templates/1/dispatch` → **HTTP 501**，返回“等真机到场联调 + 现场授权签字后开放”。
- `GET /api/v1/task-runs` → `total: 0`；`GET /api/v1/task-templates` 初始为 `[]`。
- `GET /api/v1/robots/1/tasks` → 两条 fixture 任务：“夜巡路线A” state `COMPLETE`、progress `0`；“充电任务” state `WAITTING`、progress `0`。连状态拼写都是机器人侧的原始值。
- 点位页明确写“只读：新增/修改点位要写机器人，未开放”；地图页写“草稿=平台上点的坐标，还没下发给机器人”。
- `GET /api/v1/robots/1/pose` 返回 `{"pose":{},"age_s":-1.0,"online":false}`，但 `/status` 同时说在线——两个数据源自己打架。

**为什么不能接受：**
一个巡检平台，最核心的动作是“配路线 → 下发 → 机器人跑 → 回传结果 → 形成记录”。现在下发是 501，执行记录是 0，点位不能同步，机器人数据是 fixture。**这套系统从来没有真正巡检过一次。** 演示里看到的“任务列表”是机器人 mock 返回的两条示例，不是平台跑出来的。

**甲方影响：** 12 月 1 日交付，真机 11 月 10 日才到，中间只有 3 周联调；所有写路径都锁着。这不是“功能待开放”，是**核心功能没写**（源码里 dispatch 直接抛 501）。

### 问题 2：气体/环境监测是 0 台——化工场景的命门没接

**看到的证据：**

- `GET /api/v1/sensors` → `[]`；`GET /api/v1/sensors/summary` → `{"items":{},"count":0}`。
- 驾驶舱“环境数据”六项全是 `--`：温度、湿度、可燃气体、烟雾、PM2.5、噪声；页面直接写“环境传感器未接入”。
- `/env` 页面：“还没有环境传感器。”
- `/alarm-rules` 页面：环境类（气体/烟感/温湿度/噪声）状态 **“未接入”**。
- `GET /api/v1/reports/summary` → `"environment": []`，报表里“区间内没有环境读数”。

**为什么不能接受：**
这是化工集团买“防爆巡检机器人”的第一理由。可燃气体（%LEL）、H2S、CO、O2、烟雾、温湿度，这些是泄漏和火灾的前置信号。没有传感器，这套系统就只剩“机器人位置 + 摄像头画面”，**不能叫防爆巡检，只能叫移动监控**。

**甲方影响：** 安环部不会认。出了泄漏，平台没有任何数据能证明“当时现场气体正常/异常”，事故复盘也没有依据。这个不是二期“锦上添花”，是一期必须。

### 问题 3：AI 是空壳，演示原图是 8 字节假图——可信度问题

**看到的证据：**

- `GET /api/v1/ai/results` 演示时有 2 条：表计读数 92%、区域入侵 40%。
- 点“查看原图” → `GET /api/v1/ai/results/1/image` 返回 `200 image/jpeg`，**8 字节**；十六进制是 `ff d8 ff d9 64 65 6d 6f`，即 JPEG 的 SOI/EOI 加字符串 `demo`。浏览器打开是破图。
- `server/data/ai_images/20261022/` 下 **22 个文件全部小于 100 字节**，也就是全部是这种假图。
- 全仓库 grep `inference / yolo / onnx / torch / opencv` → **0 命中**。平台没有推理代码；`/ai/results` 只是一个接收外部推送的接口。
- `/api/v1/devices` 只有一台机器人，没有算法盒/算法服务器；`/api/v1/api-clients` 里只有一个“算法盒-演示”的 Key。
- 交付包内 `docs/PPT承诺对标-投标自查-20261022.md` 自己承认：PPT 承诺“表计读数准确率 98%（已验证）”，实际 **零实现**；64 条 PPT 承诺里只有 4 条（6.3%）真正实现。

**为什么不能接受：**
平台不做推理可以理解——可以外接算法盒。但演示里**没有任何算法盒在跑**，却拿 8 字节假图冒充“原图留痕”，页面上还写着“落库存原图”。这不是“还没接”，是**演示证据造假**。在采购里，这属于可信度/合规问题，不是技术问题。

**甲方影响：** 如果合同里包含 AI 表计/缺陷识别，这条可以直接拒收；如果不在合同里，产品名和销售话术里的“AI 防爆巡检”必须改掉，否则就是虚假宣传。

### 问题 4：告警外发 500 + 报表数据自相矛盾——安全网不可信

**看到的证据：**

- `POST /api/v1/notify/channels/1/test` → **500 Internal Server Error**。
- `GET /api/v1/notify/logs?limit=5` → **500**；页面因此显示“还没有投递记录 · 0 条”，而不是“投递失败”。
- 告警统计：近 7 日 5 条，3 条未确认；其中 3 条是“机器人通信中断/升级测试：机器人失联”。
- 同一时间段的 `GET /api/v1/telemetry`：09:27、09:33 采样都是 `online: true`；但告警里 09:25、09:30 是 critical“机器人通信中断”。**同一套系统，一边说在线，一边报失联。**
- `GET /api/v1/reports/summary`：`online_ratio: 100%`；`battery_min = battery_max = 78`；`distance_m ≈ 9,900 m`。
- 选择 30 天区间（09-22 ~ 10-22）返回 `samples: 6713`；而 24 小时区间是 `6681`。**30 天报表实际只有约 18 小时数据**，但页面照常展示“30 天在线率/里程/电量区间”。
- 机器人状态页同一屏：上方“在线 / 数据年龄 0.1s”，下方“接口健康：链路在线 **否** / 数据年龄 **-1.0s** / 累计轮询 **0**”（来自 `/health/deep` 的 `cache.online=false`）。
- 报表“行驶里程 9.9 km”是用恒定 0.4 m/s × 时间算出来的；电量 18 小时恒 78%。这不是运行数据，是模拟器。

**为什么不能接受：**
告警外发是安全系统的最后一道网。测试按钮 500、投递记录 500，等于**告警发不出去，而且平台自己不知道**。报表数据又自相矛盾，安环部和审计不会信任何一张图。

**甲方影响：** 出了事，平台拿不出可信的时间线；平时做汇报，30 天报表实际是 18 小时数据。这个不是 UI 问题，是数据治理问题。

### 二期可以补（一期可用人工/降级方案）

| 项 | 为什么可以二期 |
|---|---|
| 3D 数字孪生 / 一张图 | 纯可视化层，不影响巡检闭环；用 2D 地图可先跑。 |
| 训练舱 / 模型版本 / 边缘推理 | 属于算法侧，平台先接外部算法服务。 |
| 区块链存证 | 审计哈希链已能证明“未篡改”，区块链是增强。 |
| 多机器人车队调度 / 跨场站 | 一期单机单站可先用；但接口要预留。 |
| 工单自动创建、复核角色分离 | 一期可人工转单 + 审计；二期补自动派单和复核强制。 |
| 语音对讲、远程喊话、梯控门禁、夜间声光 | 都是本体/外设能力，二期随硬件。 |
| 手机 App / 小程序 | 现在的 `/m/task/:id` 手机网页可用，先顶着。 |
| 任务日历 / 按人考核 / 缺陷类型统计 | 需要历史数据积累；一期先保证任务记录真实。 |

> 注意：**热红外/云台** 对化工场景很重要。如果合同或 PPT 明确承诺“双光测温/云台轮巡”，那就不是二期，是一期必须；如果只是演示页上的占位，必须从报价里删掉。

## 5. 对比成熟产品（海康、申昊、亿嘉和、国自）

> 说明：以下基于公开产品能力做维度对比，**没有在本环境实测竞品**；只用于判断这套系统在市场中的位置。

| 维度 | 这套系统（实测） | 海康 | 申昊 / 亿嘉和 / 国自（成熟巡检机器人厂商） |
|---|---|---|---|
| 机器人本体 | 第三方 JCROB，演示为 mock | 有机器人/视频产品线，强在视频 | 自研/成熟本体，轮式/挂轨/四足，化工/电力场景案例 |
| SLAM/导航/回充 | 平台不做，真机未验证 | 视频+AI 强，机器人看产品线 | 成熟：SLAM、避障、自主回充、爬坡/越障 |
| 载荷 | 无热像、无气体、无云台 | 视频/热成像/云台强 | 热成像、气体、声纹、局放、云台、多载荷 |

| 安全工程 | **强项**：审计哈希链、TOTP、CSRF、API Key 哈希、RBAC、强制改密 | 成熟但通常不对外展示细节 | 成熟 |
| UI/体验 | **强项**：SCADA 大屏干净、信息架构清楚、诚实标注“未接入” | 功能全但界面偏传统 | 功能全但界面偏传统 |
| 价格/灵活性 | 大概率便宜、可定制、响应快 | 中高 | 高 |

**这套的强项（要承认）：**

- 界面和驾驶舱做得比很多工业软件好，信息层级清楚，不是“表格堆”。
- **诚实**：大量“未接入/未标定/写操作未开放”的明示，不拿 0 或“正常”冒充数据；这在乙方里少见，是加分项。
- 安全工程细节扎实：审计日志哈希链 `GET /audit-logs/verify` 返回 `ok:true, checked:46`；TOTP、CSRF、API Key 只存哈希、RBAC、首次登录强制改密都做了。
- API-first、OpenAPI 契约、适配器注册表、Docker Compose 本地部署，适合做二次集成。
- 人工巡检手机页、报表导出、录像回放这些“周边功能”是真能用的。

**这套的差距（要直说）：**

- 它不是“防爆巡检平台”，是**一个第三方机器人的监控壳 + 一个人工巡检小工具**。
- 核心的机器人自主巡检、气体检测、AI 识别、多机调度、3D、国标视频、系统对接、防爆证书、项目交付，**一个都没验证**。
- 和海康比，视频/国标/AI 是代差；和申昊/亿嘉和/国自比，机器人本体、载荷、算法、案例、服务是代差。
- 它的合理定位是：**单站、单机、低成本的监控/告警/报表层**，不是集团级安全生产平台。

## 6. 如果只改三件事，优先改哪三件

### 第一件：把 mock 换成真机，把巡检闭环跑通

- 真机 11/10 到场后，第一周只做一件事：模板 → 下发 → 执行 → 暂停/继续/取消 → 回传 → 平台记录，**连续 20 次**。
- 同步打通点位同步、地图映射、状态一致性；`/pose` 与 `/status` 必须同源。
- 在闭环跑通前，**停止用 mock 数据做销售演示**；演示页必须显著标注“模拟数据”，不能把生成的地图、2021 年的时间戳、恒定电量当真实数据展示。

### 第二件：接气体/环境传感器，修好告警外发

- 至少可燃气体、烟雾、温湿度；阈值可标定；超限 10 秒内进告警中心并外发。
- 修 `notify/channels/{id}/test` 和 `notify/logs` 的 500；投递记录必须能显示“成功/失败/重试/升级”。
- 这是化工场景的命门，优先级高于 3D、AI、报表美化。

### 第三件：把“证据链”和“数据一致性”做成硬约束

- AI：每条结果必须有真实原图（非 0 字节）、时间戳、置信度、人工复核；做不到就把“AI”从产品名和报价里拿掉。
- 报表：标明实际覆盖范围，禁止拿 18 小时数据冒充 30 天；在线率、里程、电量必须与告警/遥测同源。
- 清理测试账号、测试告警、测试库、实验室画面；遥测留存从 7 天改成可配置 ≥1 年；admin 首次登录强制改密。

## 7. 一句话总结

**这套系统的 UI 和安全工程值得肯定，但它现在是一个“演示得很像”的原型：机器人是 mock、任务是 fixture、地图是画的、AI 原图是 8 字节假图、气体传感器是 0 台、任务下发是 501、告警外发是 500。**

作为化工集团信息化负责人，我的态度是：**不买当前版本；可以给一个带硬验收门槛的付费 POC。** 供应商如果能用真机把“巡检闭环 + 气体告警 + 真实证据链”跑通，再谈价格；跑不通，价格再低也不签——因为这不是省钱的问题，是安全生产系统不能拿假数据上岗。
