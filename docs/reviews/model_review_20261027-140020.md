## 一、20 个最可能出问题的点（按概率×影响排序）

### 🔴 P0 级（直接导致核心功能不可用/数据错误/安全问题）

#### 1. 真机巡航任务在 X30 上整条链路跑不通（概率最高，已知未验证）
- **触发步骤**：
  1. admin 登录，新建巡航模板（添加 3 个点位，每个点位配置"停留 10s + 拍照"动作）
  2. 选择在线 X30 设备，立即下发巡航
  3. 观察：任务状态是否从"待执行→执行中"、逐点下发指令是否成功、轮询位置是否到点、到点后拍照动作是否触发、任务结束状态是否正确
- **翻车点**：TCP 30000 状态通道和 UDP 43893 动作通道协议不匹配；点位坐标系与机器人坐标系不一致；轮询超时时间设置过短；到点判定阈值不合理导致永远在"前往中"；UDP 指令丢包无重试。

#### 2. 单 uvicorn worker 下，视频转码 + WS 传感器 + 巡航轮询互相阻塞
- **触发步骤**：
  1. 同时打开 4 路视频（其中 2 路 H265 触发转码）
  2. JCROB 设备上线并建立 2 路传感器 WS（3547）
  3. 下发一条巡航任务，同时 10 个浏览器打开大屏
  4. 观察：API 响应延迟、WS 消息延迟、ffmpeg 进程 CPU 占用、任务轮询是否超时
- **翻车点**：所有 I/O 阻塞事件循环；WS 心跳挤占协程；转码进程 stdout/stderr 未异步读取导致管道阻塞死锁；单 worker 无横向扩展能力，CPU 跑满后整个平台卡死。

#### 3. 告警去重/滞回/持续时间组合逻辑产生"告警消失"或"风暴"
- **触发步骤**：
  1. 配置温度阈值：高报 30℃，持续 5s，滞回 2℃，去重窗口 60s
  2. 模拟传感器数据：29℃（10s）→ 31℃（3s）→ 29℃（2s）→ 31℃（持续）
  3. 再在 60s 内反复在 28~31℃之间跳变 20 次
- **翻车点**：持续时间计时器在数值波动时被重置但未正确恢复；滞回逻辑用绝对值而非"恢复到阈值-滞回量"；去重 key 生成遗漏设备/点位维度导致跨设备错误去重；P1~P4 分级边界值计算错误；告警恢复事件丢失导致永远处于告警态。

#### 4. 审计哈希链断裂后，一键校验误报"通过"或直接 500
- **触发步骤**：
  1. 正常产生 100 条审计日志
  2. 直接在数据库修改中间第 50 条的 operation 字段
  3. 删除第 70 条记录
  4. 在第 80 条后插入一条伪造记录
  5. 点击"一键校验"
- **翻车点**：只校验首尾哈希；分页校验导致中间断链未发现；空表/单条记录时报错；时间倒序数据未重排；哈希算法拼接字段遗漏（如 IP、UA）；篡改后无具体定位（哪一条断了）。

#### 5. JWT + CSRF + 空闲超时 + 多标签页的组合状态错乱
- **触发步骤**：
  1. 同一账号在两个标签页登录
  2. A 标签页空闲 5 分钟（不操作），B 标签页持续操作
  3. 在 A 标签页点击"告警搁置"
  4. 再测试：A 退出登录后 B 标签页是否还能操作；CSRF token 过期后刷新页面是否能自动续期；锁定后使用旧 token 是否能调通接口
- **翻车点**：空闲超时基于会话而非 token，旧 JWT 在锁定期仍可用；双提交 cookie 的 CSRF token 未与 session 绑定导致可伪造；多标签页共享 cookie 导致一个退出全退出但前端状态不同步。

#### 6. 告警搁置到期后未自动恢复，或搁置期间升级仍被触发
- **触发步骤**：
  1. 产生一条 P1 告警，搁置 1 分钟，原因填写
  2. 观察 SLA 超时计时是否暂停
  3. 1 分钟后观察是否自动恢复告警状态
  4. 搁置期间手动确认告警，检查权限与状态流
- **翻车点**：搁置只改了展示状态，后台升级定时任务仍在跑；到期恢复任务是一次性定时任务，服务重启后全部丢失；无权限用户可通过越权 API 搁置告警；搁置原因允许空字符串。

#### 7. H265→H264 转码进程泄漏（无人看后不退出/僵尸进程）
- **触发步骤**：
  1. 打开 H265 视频流，确认 ffmpeg 转码进程启动
  2. 直接关闭浏览器标签页（不点停止）
  3. 断开网络 2 分钟后恢复
  4. 反复开关 20 次，执行 `ps aux | grep ffmpeg` 查看进程数
- **翻车点**：只靠 WebSocket onclose 触发停止，浏览器异常断开未检测；go2rtc 观察者计数不准（同一用户多次打开累加但关闭只减一次）；ffmpeg 进程变成僵尸进程无人回收；共享 MJPEG 流的引用计数错误导致有人看也被停。

#### 8. JCROB WebSocket 传感器断连重连后数据重复/外设重复创建
- **触发步骤**：
  1. JCROB 设备正常上线，确认自动创建了温度、湿度、PM2.5 等传感器和外设
  2. 断开设备网络 30s 后恢复（WS 重连）
  3. 反复断连 5 次，查看传感器列表
- **翻车点**：重连后用"设备+类型"查询不唯一导致重复插入；自动创建外设时无唯一约束；断连期间数据缓存后重放导致历史数据时间戳错乱；EnvSensorData 和 AirSensorData 两路 WS 生命周期不同步导致一半传感器在线一半离线。

#### 9. 角色越权：7 种角色的垂直/水平权限边界存在未设防接口
- **触发步骤**：
  1. 用 viewer 账号登录，抓取以下接口直接调用：
     - POST `/api/tasks/execute`（下发任务）
     - POST `/api/alarms/shelve`（搁置告警）
     - DELETE `/api/users/{id}`（删除用户）
     - GET `/api/audit/logs`（查看审计）
     - POST `/api/system/write-switch/enable`（开写开关）
  2. 用 safety 角色尝试派单、用 operator 尝试查看审计日志、用 auditor 尝试控制机器人
- **翻车点**：只在前端菜单做了角色控制，后端接口缺 `@require_role` 装饰器；JWT 里 role 字段可被篡改（无签名校验或算法为 none）；安全三员（sysadmin/secadmin/auditor）权限未分离，sysadmin 可删审计。

#### 10. 工单 SLA 超时升级在服务重启/时间跳变后失效或重复升级
- **触发步骤**：
  1. 创建 SLA 时限为 5 分钟的 P1 工单，不接单
  2. 2 分钟后重启后端服务
  3. 等待超过 5 分钟，观察是否升级
  4. 再测试：修改服务器时间向后跳 10 分钟、向前回拨 5 分钟
- **翻车点**：升级逻辑只靠内存定时任务（APScheduler 未持久化），重启全部丢失；时间回拨导致定时任务永远不触发；重复升级（每次重启扫描一次就升级一次，无升级状态标记）。

### 🟠 P1 级（重要功能异常/数据不准/体验严重受损）

#### 11. 巡航"逐点下发 + 轮询"无超时无取消，任务卡死无法终止
- **触发步骤**：
  1. 下发巡航任务，在机器人前往第一个点位途中：
     - 拔网线（设备离线）
     - 人为挡住机器人（真机）
     - 点击"中止任务"
  2. 观察任务状态、后续点位是否继续、能否重新下发任务
- **翻车点**：设备离线后轮询无限重试不超时；中止指令只改数据库状态，实际机器人还在动；前一个任务卡死后设备被锁，无法下发新任务（任务占用状态未释放）。

#### 12. 大屏三栏在"设备无某能力"时面板白屏/报错/布局塌陷
- **触发步骤**：
  1. 对接一台只有视频、无云台、无测温、无环境传感器的设备
  2. 对接一台只有环境传感器、无视频的设备
  3. 对接一台 X30（有起立趴下、无空气传感器）
  4. 分别查看大屏，切换不同设备
- **翻车点**：前端 v-if 判空不彻底，读取 `device.capability.ptz.pan` 直接抛 TypeError；能力派生面板规则遗漏新增设备类型；切换设备时旧 WS 未断开导致数据串台（A 设备大屏显示 B 设备温度）。

#### 13. Excel 报表导出在大数据量/空数据/特殊字符时崩溃或数据错位
- **触发步骤**：
  1. 导出时间范围 1 年的巡检记录（预计 10w+ 行）
  2. 导出筛选后结果为 0 条的报表
  3. 在告警原因、工单备注、搁置原因中输入 emoji、换行、Excel 公式（`=cmd|' /C calc'!A0`）、单引号后导出
  4. 导出过程中再次点击导出按钮
- **翻车点**：一次性全量 load 到内存 OOM；空数据导出空文件无提示；CSV/Excel 公式注入导致打开文件执行命令；列名与数据列错位；并发导出导致文件名冲突互相覆盖。

#### 14. 写开关默认关，但多条任务路径绕过开关直接下发指令
- **触发步骤**：
  1. 确认写开关为关闭状态
  2. 分别尝试：手动点云台控制、起立/趴下、立即执行拍照模板、启动巡航、工单销号回传
  3. 抓包确认是否真的未向设备发送写指令
- **翻车点**：只有巡航接口判断了开关，手动控制接口漏判；开关只在前端置灰按钮，后端不校验；开关状态在内存中，重启后恢复默认（或预期一致但多实例不一致）。

#### 15. TOTP 绑定/验证流程存在重放窗口与时钟漂移问题
- **触发步骤**：
  1. 绑定 TOTP 后，使用同一个 6 位验证码连续提交 2 次
  2. 将客户端/服务器时钟分别调快/调慢 1 分钟、5 分钟、10 分钟
  3. 输入剩余有效期 <3s 的验证码
- **翻车点**：同一 code 可无限次重放（无 nonce 防重放）；时间窗口只允许 ±30s，时钟漂移稍大即无法登录；TOTP 密钥在绑定确认前就已生效，绑定半途退出导致账号被锁。

#### 16. 登录锁定 5 次/10 分钟可被绕过（IP/账号维度设计错误）
- **触发步骤**：
  1. 对同一账号从 2 个不同 IP 各尝试 3 次错误密码
  2. 对同一 IP 尝试 4 个不同账号各 2 次
  3. 等待 10 分钟后再试
  4. 锁定后使用正确密码 + TOTP 登录
- **翻车点**：只按 IP 计数，攻击者换 IP 可暴力破解；只按账号计数，攻击者可通过恶意锁定使管理员无法登录（DoS）；计数窗口用滑动窗口实现错误，第 5 次失败后实际锁定时间不足/超长；成功登录后失败计数未清零。

#### 17. 环境传感器单位/量纲/精度不一致导致阈值告警全错
- **触发步骤**：
  1. 核对 EnvSensorData（温度℃、湿度%）和 AirSensorData（PM2.5 μg/m³、CO₂ ppm）上报单位
  2. 模拟器分别上报：温度 300.5（异常值）、湿度 -10、PM2.5 0、null 值、缺字段
  3. 阈值设为 30℃，上报 30.0、29.99、30.001
- **翻车点**：设备上报开尔文/华氏度未换算；浮点精度导致 29.999999 被误判；null/异常值未被过滤直接触发告警或导致规则引擎 NPE；两路传感器同名字段（如温度）互相覆盖。

#### 18. 手机 H5 工单销号拍照上传：大图、弱网、断点导致失败或数据脏
- **触发步骤**：
  1. H5 接单后上传一张 20MB 照片（4G 网络）
  2. 上传到 50% 切后台、杀进程、断网
  3. 同一工单用两台手机同时销号
  4. 上传非图片文件改后缀为 .jpg
- **翻车点**：无分片/无断点续传导致弱网必失败；无文件类型魔术字校验；重复销号生成两条完成记录；图片存储路径可遍历；H5 登录态与 PC 端冲突互相踢下线。

#### 19. 系统状态页展示"假在线"：服务在但链路实际不通
- **触发步骤**：
  1. 设备 TCP 30000 端口不通但心跳进程假活
  2. go2rtc 进程在但流地址 404
  3. MySQL 连接池耗尽（磁盘满）
  4. JCROB WS 是 TCP 连接存活但无数据上报（设备端假死）
- **翻车点**：健康检查只做 TCP 端口探活，不做业务级探活；连接池满后状态页自身也查不了库直接 500；设备在线判定只靠心跳，上报通道断了 10 分钟仍显示在线。

#### 20. 时区/时间格式问题：UTC 与本地时间混用导致报表与 SLA 错位
- **触发步骤**：
  1. 将服务器时区设为 UTC，浏览器设为北京时间（UTC+8）
  2. 生成一条 23:55 的告警，SLA 10 分钟，查看"按日统计报表"归属哪一天
  3. 导出 Excel 后核对时间列
  4. 跨午夜执行巡航任务，查看巡检覆盖度报表
- **翻车点**：数据库存 naive datetime；前端直接 new Date() 显示不带时区转换；SQL `DATE(create_time)` 用服务器时区导致跨天数据错位；定时任务按服务器时区执行但用户预期按本地时区。

## 智谱 GLM（glm-5.2）

作为甲方测试经理兼竞品测试架构师，我直接拍砖。这套系统典型的“功能堆砌完成，工程化打磨不足”，单机单进程（`uvicorn` 单 worker）部署 FastAPI 跑重型同步任务（视频、串口、长轮询）是架构上的致命伤。

以下是针对该系统的对抗式测试设计与问题剖析。

---

### 一、 20 个最可能出问题的点（按 `发生概率 × 影响程度` 排序）

1. **单进程并发阻塞（P0×致命）**：FastAPI 单 worker，若视频控制或巡航轮询遇到网络超时，整个后端 API 阻塞，大屏刷新全部超时白屏。触发：拔掉机器人网线，触发巡航。
2. **真机巡航指令积压/死锁（P0×致命）**：已知“真机没跑过”，逐点下发+轮询机制在弱网下极易卡死在某一点，后续任务全挂。触发：连接 X30 真机，下发 5 点巡航，中途关闭机器人 30 秒再开机。
3. **go2rtc H265→H264 转码 CPU 雪崩（P0×高）**：单机部署，多路 H265 同时拉流转码，CPU 占用瞬间 100%，导致 MySQL 和 FastAPI 无响应。触发：同时打开 3 路 X30 视频流。
4. **JWT 自动续期与超时竞争（P1×高）**：空闲 5 分钟自动退出，如果用户在第 4 分 59 秒提交工单，后端校验 Cookie 时刚好过期，前端无感丢失数据。触发：卡点在临近超时时提交长文本表单。
5. **审计哈希链断链（P1×高）**：高并发写操作（如环境传感器高频上报触发连续告警）导致 DB 事务交错，上一条记录哈希未生成，下一条已写入，哈希校验一键失效。触发：模拟 10 个传感器同时越限告警。
6. **WebSocket 断线重连风暴（P1×高）**：JCROB 环境 WS 连接断开后，若无指数退避重连机制，每秒疯狂重连，打满端口或 CPU。触发：重启 JCROB 机器人，观察后端日志。
7. **CSRF 双提交与 H5 工单冲突（P1×高）**：手机端 H5 如果不在同域， CSRF Token 获取机制可能失效，导致外勤人员无法销号。触发：使用 4G 网络访问 H5 工单页面拍照上传。
8. **空数据导致前端崩溃（P1×中）**：新部署无设备、无告警时，大屏 Echarts 图表可能因 `undefined` 报错白屏。触发：清空数据库所有告警和点位，访问大屏。
9. **超长文本/特殊字符击穿组件（P1×中）**：工单搁置原因或告警去重规则中输入超长字符串或 Emoji，导致 MySQL `Data too long` 报错或前端 DOM 溢出。触发：在工单销号备注粘贴 1 万字文本。
10. **SLA 超时升级死循环（P1×中）**：工单超时升级到上级，若上级也超时，缺乏最终兜底状态，可能陷入无限升级或状态机锁死。触发：将 SLA 时限设为 1 分钟，不处理工单观察 10 分钟。
11. **时区错乱导致 SLA 误判（P1×中）**：服务器 UTC，前端本地时间（UTC+8），导致 SLA 计时提前 8 小时超时。触发：检查数据库时间戳与前端展示时间是否一致。
12. **go2rtc 僵尸进程耗尽内存（P2×高）**：大屏关闭后，ffmpeg 转码进程未按预期“无人看自动停”，变僵尸进程，日积月累 OOM。触发：频繁打开关闭视频流 20 次，查系统进程列表。
13. **X30 UDP 丢包导致状态不同步（P2×中）**：UDP 43893 发送趴下/站起指令无确认机制，弱网下前端显示成功但机器未动作。触发：注入 30% 丢包，下发站起指令。
14. **设备多态面板渲染异常（P2×中）**：按外设能力派生面板，当设备掉线导致能力字典缺失时，面板报错。触发：巡检途中断开机器人连接，观察大屏左侧面板。
15. **ffmpeg MJPEG 拉流内存泄漏（P2×中）**：服务端共享 ffmpeg 转 MJPEG，单机内存有限，长时间运行极易 OOM。触发：挂机 24 小时持续拉取 MJPEG 流。
16. **环境传感器自动去重失效（P2×中）**：阈值在临界点上下波动（如温度 50.01 与 49.99），若滞回区间设置不当，每秒产生上百条告警打爆 DB。触发：模拟温度在阈值线高频震荡。
17. **任务模板“写开关”默认关引发的误测（P2×低）**：测试人员测了半天录像没生成，发现是全局写开关默认关。触发：直接下发录像任务。
18. **TOTP 时间窗偏移导致锁定（P3×中）**：手机时间和服务器差 1 分钟，连续输入 5 次TOTP 导致账号锁定 10 分钟。触发：故意拨慢手机时间测试。
19. **测试数据污染报表哈希（P3×低）**：已知历史有测试数据，如果直接上线，报表考核数据惨不忍睹，且哈希链包含脏数据。触发：直接查看覆盖度报表。
20. **MySQL 死锁（P3×中）**：工单派发（更新状态）与 SLA 超时扫描（查询并更新）并发操作同一批数据，偶发死锁。触发：批量导入 1000 个工单并触发 SLA 扫描。

### 三、 5 个“看起来会过、实际会翻车”的场景

1. **并发拉流场景（资源击穿）**
   * **假象**：测试单路视频播放很流畅。
   * **翻车**：安保班长和主管同时在大屏和手机端查看同一个 X30 的视频。go2rtc 对同一路流有共享机制尚可，但如果是不同流（一个是 H264_web，一个是 MJPEG），单机 CPU 直接 100%，导致 MySQL 连接超时，整个系统假死。
2. **断网弱网巡航（状态机死锁）**
   * **假象**：模拟器上巡航完美无缺，逐点下发丝滑。
   * **翻车**：真机在巡检点之间移动时，进电梯断网 1 分钟。后端轮询一直卡在 `is_moving` 状态。由于单 worker，这个卡死的协程可能导致整个任务调度模块僵死。网络恢复后，机器人已到达点位，但系统认为还在移动，不发动作指令，任务永久挂起。
3. **UTC 时区错位（SLA 计时黑洞）**
   * **假象**：本地测试创建工单，10 分钟超时，等 10 分钟确实超时了。
   * **翻车**：服务器是 Docker 默认 UTC 时间，前端是北京时间。半夜创建的工单，因为跨天计算，导致 SLA 倒计时直接变成负数或跨越 8 小时瞬间超时，引发批量误升级。
4. **空数据与极限数据（前端渲染崩溃）**
   * **假象**：造了几条测试数据，报表导出、图表渲染正常。
   * **翻车**：全新系统上线第一天，没有任何巡检记录，Echarts 拿到空数组直接渲染导致 `Cannot read property 'value' of undefined`，大屏白屏。或者环境传感器上报的 PM2.5 是 `null` 而非 `0`，导致告警阈值对比 JS 报错。
5. **超长文本/特殊文件名（DB与OS截断异常）**
   * **假象**：工单备注随便打几个字，正常。
   * **翻车**：现场人员手机拍照，照片名是系统自动生成的带时间戳超长字符串，或者销号备注里粘贴了一大段报错日志（超过 MySQL VARCHAR 255 限制）。后端没做长度校验，直接抛出 SQL 异常，前端收到 500 错误，工单死活销不掉。

### 四、 真实事故案例与吸取的教训

1. **某省安防视频平台 OOM 宕机事件**
   * **案例**：类似 go2rtc + ffmpeg 架构，由于
