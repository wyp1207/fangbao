## 2. 本轮联调抓到的三个真问题（都已修）

### P0-1 并发写审计 → 哈希链断裂

- **现象**：D3 第一次跑失败：`{"ok": false, "broken_at": 991, "reason": "prev_hash 对不上（可能缺行）"}`
- **根因**：`audit()` 先查最后一条 `row_hash` 再插入。并发时两个请求读到同一个 last，
  生成两条相同 `prev_hash` → 链断。**这正是 GLM 预测的"审计链与业务并发冲突"**。
- **修复**：`messages._AUDIT_LOCK` 串行化整段写入（单 worker 足够）。
- **回归**：新增 A5，6 个并发写后校验仍 `ok=true`（checked=1181）。

### P0-2 `/robots/{id}/motion` 500

- **现象**：H1 首次 500。
- **根因**：`build_for(robot)` 缺 `settings` 必填参数（同一处缺陷此前也出现在 init-loc）。
- **修复**：传 `settings=get_settings()`；新增 `if not supported → 400 NOT_SUPPORTED` 的契约用例。

### P2-1 前端外壳未起时用例直接报连接失败

- **处理**：C4 明确依赖 5173；未起时判 FAIL 并提示启动 Vite，而不是"前端有问题"。

## 4. 做不了的部分（诚实版）

### 4.1 需要真机/HIL，当前无条件

| 项 | 为什么做不了 | 替代能覆盖到哪 | 验收材料怎么写 |
|---|---|---|---|
| 物理按键/GPIO 时序（抖动、长按、连击） | 没有 HIL 机柜，也没有按键硬件 | 用 `POST /motion` 模拟"事件入口"，验证后端契约与拒绝路径 | "平台侧事件入口已验；电气时序需 HIL" |
| X30 TCP 0xEB90 报文/端序/UDP 控制 | 设备在厂区且当前不通 | 仅协议解析单测（16 字节头、XML 体） | "协议解析单测通过；端到端未验" |
| 到点漂移与 `arrive_radius_m` 实调 | 需真实定位漂移 | 模拟器可造 0.5/1.5/4m 三档 | "三档判定已验；实车漂移待现场标定" |
| 断网/弱网（netem/丢包） | 本机无管理员网络配置权限 | 可拔模拟器进程模拟"设备失联" | "失联路径已验；弱网未验" |
| 磁盘写满/保留期清理 | 破坏性，需独立卷 | 单测覆盖清理 SQL | "清理逻辑单测；满盘演练未做" |

### 4.2 需要压测集群/多实例

| 项 | 现状 | 说明 |
|---|---|---|
| 分布式压测（Rhino/PTS 级） | 无 | 单机 A1/A2 只能给"单实例基线"，不能说"支撑 N 并发" |
| 全链路流量染色 | 无 | 单 worker + 单库，染色收益低 |
| MQ/网关路由/死信 | 架构里没有 MQ | 该项对我们是 N/A，不是"缺失" |
