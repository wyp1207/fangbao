## 0. 一句话结论

**两个模型独立给出的定级都是 L1（演示可用级）**，且都把「真机最小链路未验证」列为一号问题。
我们同意 L1 的结论，但不同意"什么都没有"——**测试/安全两块已达 L2–L3 水平**，短板集中在
**真机、架构（单 worker/无 MQ/无时序库）、运维（无容器化/无备份）、交付（无实施手册）**。

## 3. 事实核查（模型说错/夸大的，必须纠正，别拿去误导决策）

| 模型说法 | 事实 | 证据 |
|---|---|---|
| "仅 Web 页面告警，无外部通知" | ❌ 已有**企业微信/钉钉/通用 webhook/邮件**四通道，可配 | `server/app/services/notify.py:1`、`channels` 定义 |
| "进程内资源锁无超时释放" | ❌ 有 **TTL + 字典序抢锁**，过期只告警不自动释放（防撞车） | `server/app/services/resource_lock.py`、`tests/test_resource_lock.py` 4 例 |
| "8 并发下发只成功 1 次 = 并发能力极差" | ⚠️ 这是**设计**（一车一任务互斥），不是吞吐上限；但确实说明我们**没有吞吐型压测** | `task_lock.assert_free`、联调 A2 |
| "无任何测试/质量门禁" | ❌ 106 pytest + 24 联调 + 34 路由冒烟 + 越权/注入/审计篡改 | `server/tests`、`scripts/integration_suite.py`、`ui_smoke.py`、`adversarial_test.py` |
| "审计日志可被 admin 删光" | ⚠️ 部分对：DB 级删除无法阻止（无 WORM/异地），但**篡改可被哈希链定位** | `verify_audit_chain` 返回 `broken_at` |
| "无任何安全能力，等保必挂" | ⚠️ 部分对：应用层已达标（CSRF/TOTP/RBAC/审计）；**设备侧与合规材料确实缺** | 同上 |

## 4. 定级与"跳 L2 缺什么"

**当前：L1+（可在客户现场做 POC/单机试点，不能承诺 7×24 生产运行）**

L2 门槛（模型一致口径）：10–50 台、分层架构 + MQ + 时序库 + 基本监控。
我们离 L2 的差距按依赖顺序：

| 优先级 | 缺口 | 为什么先做 | 验收 |
|---|---|---|---|
| P0 | **真机最小闭环** | 一切假设的验证前提 | X30 连续 2h：注册/心跳/单点下发/定位回传成功率 ≥99%，断网 30s 恢复 10s 内重连 |
| P1 | **设备接入安全**（一机一密 + 报文签名/白名单） | 内网可控车 = 法律风险 | 伪造报文拦截 100%；100 条畸形报文不崩 |
| P2 | **部署与备份标准化**（一键脚本 + 每日备份 + 恢复演练） | 现场第一周必踩 | 全新机器 30min 起全服务；备份恢复后审计链完整 |
| P3 | **可观测与外部告警**（结构化日志 + 端口/报文成功率 + 短信或电话 webhook 兜底） | 出事没人知道 = 最大运维成本 | 设备离线/指令失败 10s 内页面+外部通道告警 |
| P4 | **MQ + 时序库拆分**（L2 硬门槛） | 单 worker 撑不住多设备 | 10 台模拟设备 1Hz 上报，API p95 不劣化 2 倍 |

> 我们的判断：**P0 不做完，P1–P4 都是沉没成本**（与豆包"如果只能改一处"一致）。
> 但 P1/P2 可以并行——它们不依赖真机，且都是 2–3 人天的活。

## 5. 两周计划（把模型建议收敛成能交差的）

| 周 | 事项 | 产出 | 验收 |
|---|---|---|---|
| W1 | 真机对接（X30 优先）：协议抓包、1002/1003/1007 实报文、粘包/半包处理、状态码映射 | `docs/真机联调记录.md` + 修完的适配器 | 单点下发→到达→回传 20/20 |
| W1 | 设备接入安全：token/签名校验开关 + 白名单 + 畸形报文容错 | 中间件 + 单测 | 伪造/无签名 100% 拒；畸形 100 条不崩 |
| W2 | 部署脚本（venv+alembic+systemd/计划任务）+ 每日备份 + 恢复演练 | `scripts/deploy.sh`、`scripts/backup_db.py` | 新机器 30min 起；恢复演练通过 |
| W2 | 观测补齐：结构化日志（request_id/device_id）、端口与报文成功率、外部告警通道兜底 | 状态页增强 | 断网 10s 内告警到企微/钉钉 |
| 持续 | 真机回归纳入联调套件（新增 5–8 条真机用例） | 报告 | 每版必跑 |

## 6. 对客户/领导怎么讲（诚实版，三句话）

1. **已经能做的**：单机部署、任务编排与逐点巡航、告警闭环（含搁置/SLA/工单）、审计与权限、环境数据接入；软件侧有 106 单测 + 24 联调 + 34 路由冒烟可复跑。
2. **还没证明的**：真机链路（X30/JCROB 现场未通）、7×24 长稳、多机协同与多地图、等保/防爆合规材料。
3. **建议的节奏**：先做 **2 周真机联调 + 部署/备份标准化**，再谈多机与集群；在此之前不承诺"生产级/百台级"。
