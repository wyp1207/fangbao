# 三维孪生演示脚本（8 分钟版）

> 目标：让客户/领导在 8 分钟内确认两件事——**这是真数据在动**，**坐标是准的**。
> 配套：`python scripts/demo_prep.py`（一键准备：开写开关、跑自检、造一条演示告警）。

---

## 0. 演示前 5 分钟（照清单打勾）

| # | 检查 | 命令/位置 | 不通过怎么办 |
|---|---|---|---|
| 1 | 后端活着 | 浏览器开 `/health` 返回 ok | 重启服务，看 `journalctl -u jc-robot` |
| 2 | 前端打开 | 登录后首页四块面板都有数 | 检查 `npm run dev` 或 nginx |
| 3 | 写开关 | 系统设置 → 下发开关 = 开 | 演示"只读"是扣分项 |
| 4 | 自检 | 系统状态 → 运行自检 | 只有"真机离线"允许红，其他项必须绿 |
| 5 | 演示数据 | `python scripts/demo_prep.py` | 会造一条「演示-可燃气体」告警 |
| 6 | 浏览器 | 全屏（F11）、缩放 100%、关插件 | 截图会给客户看，边框都不要 |
| 7 | 兜底 | 提前截好 `docs/screenshots/twin-*.png` | 网络/机器出问题时切图讲 |

## 1. 开场（30 秒，先定调）

> "这是**实时数字孪生**，不是渲染动画。大屏上机器人的位置、告警、轨迹，全部来自现场设备，
> 刷新 200 毫秒一次。所以它看起来不如效果图华丽，但它**是真的**。"

**为什么先说这句**：客户脑子里是那张 3D 效果图，不先定调，后面一定被问"怎么不像"。

---

## 2. 首页（1 分钟）

动作：打开 `/dashboard`，鼠标依次指四块面板。

| 指哪里 | 说什么 |
|---|---|
| 左上机器人状态 | "电量、状态、定位、数据年龄——**数据年龄**这栏是关键，超过 3 秒就说明链路有问题" |
| 告警统计 | "近 7 日告警 206 条，P1/P2 分级，未确认多少条一眼看到" |
| 环境数据 | "温湿度、可燃气体、CO₂，都是设备实时推上来的" |
| 视频 | "可见光 + 热红外，没人看的时候转码自动停，不占 CPU" |

**不要做**：不要逐条念数字。

---

## 3. 三维孪生（4 分钟，主菜）

打开 `/twin`。

### 3.1 先讲"是什么"（30 秒）

> "底下这张是机器人自己扫出来的 SLAM 地图，我们把墙按高度拉起来，所以：
> **机器人在这张图上的位置，和现场是同一套坐标**，不需要人工对齐。"

鼠标操作：拖动旋转 → 滚轮拉近 → 指墙体和点位标签。

### 3.2 让它动（1 分钟）★ 最关键

动作二选一：

- **模拟器**：任务执行页 → 下发一条短巡航 → 回 3D 看机器人沿点位走
- **真机**（如果通了）：首页点「起立」→ 车动 → 3D 同步

> "注意看，机器人是**连续滑动**的，不是一秒跳一下——位姿走 WebSocket，200 毫秒一帧，前端做插值。"

看 HUD 右上角：应显示 `WS 200ms`。**如果显示"轮询 1s"，说明 WS 没连上**，先别讲这句。

### 3.3 告警光柱（1 分钟）

动作：提前造的「演示-可燃气体」告警会在机器人附近显示**红色光柱 + 扩散光环**。

> "告警不是列表里的一行字，它在空间里有位置——**值班的人一眼知道该往哪跑**。"

若现场没显示：在告警页找到那条告警，指列表也可以（别硬撑）。

### 3.4 轨迹回放（1 分钟）★ 最能证明"真"

动作：

1. 面板选「最近 24 小时」
2. 点「播放」，看时间从昨晚走到现在
3. 拖时间轴到任意时刻
4. 变速 30×

> "拖到昨天下午三点，就能看到它当时在哪、走了哪条路。**参考图做不到这个，只有真数据能。**"

HUD 会显示 `1215 点 / 7116 m`（数字会随数据变，别说死）。

### 3.5 三个开关（30 秒，展示"可调"）

| 开关 | 演示说法 |
|---|---|
| 高度分层 | "关掉是统一高度，打开按墙体厚度分高矮——**现场调，不改代码**" |
| 阈值 | "地图脏、噪点多的时候调这个，墙会变干净" |
| 光效 | "Bloom + 扫描线，好看但吃显卡；**帧率低会自动关**，工控机也能跑" |

---

## 4. 自检页（1 分钟，展示"能定界"）

动作：系统状态 → 运行自检。

> "接不上设备的时候，不用工程师到场——点一下就知道是**平台、网络还是设备**的问题，
> 每条还给处理建议。这是给现场运维用的，不是给你们看的。"

（这条对甲方运维部门特别加分。）

---

## 5. 收尾（30 秒）

> "现在能演示的是单机巡检全流程：任务、告警、审计、3D 孪生、轨迹回放。
> 下一步两件事：**真机联调**（11 月 10 日设备到场）和**关键设备白模**（储罐、管廊那 5–10 个）。
> 白模一上，观感会明显接近效果图；但**坐标和实时性现在已经是对的**。"

---

## 6. 必被问到的 6 个问题（背下来）

| 问题 | 回答 |
|---|---|
| **"怎么不像我们场站？"** | "这版是 SLAM 数据驱动的**坐标底模**，先保证点位、轨迹、告警实时准确；外观复原需要关键设备白模，下一阶段补 5–10 个就能明显改善。" |
| **"为什么不用 UE5？"** | "UE 要独显工作站，浏览器跑不了；我们 WebGL 方案工控机开箱即用，运维零成本。" |
| **"点云呢？"** | "点云是建图产物，运行时 50Mbps 传不动；底图用栅格地图持久化，需要时可以叠降采样点云。" |
| **"帧率多少？"** | "这台机器（现场核显）现在 XX 帧；软件渲染下会低，所以我们做了**低帧率自动关光效**。"（数字现场读 HUD，别说 60） |
| **"机器人怎么不动？"** | "这是模拟器/真机没下发；您看位姿年龄——超过 3 秒就是链路问题。"（顺势演示自检） |
| **"能管几台车？"** | "软件支持多台接入；当前只有 1 台真机，多机协同还没实车验证——**这个我不吹**。" |

## 8. 三种翻车场景与兜底

| 场景 | 兜底 |
|---|---|
| WS 没连上（显示"轮询 1s"） | 不讲"200ms"，改讲"坐标是准的 + 轨迹回放"；会后查 nginx Upgrade 头 |
| 3D 页面白屏/报错 | 切提前截的图，讲同样的内容；同时开系统状态页证明服务是活的 |
| 帧率很低、卡顿 | 关「光效」；再关「高度分层」；还卡就缩小浏览器窗口（不是全屏 4K） |
| 机器人不动 | 立刻切到自检页，把"设备离线"变成"我们能定界"的加分项 |
| 客户说"这就是个游戏画面" | 拖轨迹回放到一个具体时间点，让他说一个时间，你拖过去——**只有真数据经得起随机抽查** |
