## 2. 为什么搁置

X30 的定位初始化不是"点一下按钮"能解决的：

1. 导航/定位进程需要先启：`ssh ysc@192.168.1.106` → `bash ~/jy_cog/system/scripts/start_nav.sh`
2. 必须在 **RViz** 里点 `[2D Pose Estimate]`，按机器人实际位置和朝向拖箭头
3. 成功的判据是"激光点云与栅格地图重合"，`/location_status` 变 0
4. 机器人当前 `Location=1`（定位丢失）、位姿在地图外，**任何导航指令都是危险的**

平台做不了第 2 步：RViz 的交互是"看激光点云对齐"，不是选一个坐标就能替代的。
在平台上做个"提示向导"没有用——用户要的是能走，不是看提示。

## 3. 已经做完的（恢复时直接可用）

- **真机地图导入**：`jueying.pgm` 1051×1351 @0.1m/px，origin (-57.9, -53)，已进地图库
- **X30 适配器**：1002 解析（含 Location 语义修正 0=正常/1=丢失）、2101 重置定位、1003 导航（带 MapID）、1004 取消、1007 轮询
- **平台接口**：
  - `POST /robots/{id}/goto`（单点，带写开关/在线/急停/电量/任务占用/地图栅格/距离确认六道闸门）
  - `POST /robots/{id}/motion-mode`（起立/趴下/开始运动/停止运动）
  - `POST /robots/{id}/move`（三轴速度，按住走松手停）
- **巡航状态机**：逐点下发 → 1007 轮询 → 到点三态（arrived/suspect/failed）→ 动作 → 下一点；断点续跑；取消回读
- **真机实测**：起立、开始运动、前进、停止 全流程通过（2026-10-28）

## 5. 恢复前必须先确认的三件事

1. **MapID**：1002 不上报，只有控制器/实测能确认。默认 1（老平台 dispatch.py 也用 1）
2. **地图一致性**：1002 的原始返回带 `X0/Y0/H/Res`，平台可以拿它和地图库比对（已记录，未实现自动校验）
3. **安全**：巡航前必须 `located=true` 且目标点在空闲栅格；场地清空、急停在手

## 7. 不做什么（避免浪费）

| 不做 | 原因 |
|---|---|
| 平台内嵌 RViz / 重写定位初始化 | 需要 3D 点云交互 + ROS 桥，投入大、收益低；现场 15 分钟能解决 |
| 用"提示向导"代替 RViz | 提示解决不了"点云和地图对不齐"，用户要的是能走 |
| 无定位时下发导航 | 危险，平台已强制拦截 |
