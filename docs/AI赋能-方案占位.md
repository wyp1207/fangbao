# AI 赋能 · 方案占位（先不实现）

> 结论：**现在不接任何大模型**。本文只回答"将来要接，接在哪、怎么接、怎么不添乱"。
> 2026-10-22 定：真机联调 + P1 稳定项做完之前，不动这条线。

## 一、服务器上有什么

- **Qwen3-32B**（推理质量好，显存占用高）
- **Qwen3-8B / 27B**（速度快，适合高频调用）

两个都是**文本模型**，能读会写，但**看不了视频画面**。

## 二、能做什么（按可行性）

| 场景 | 可行性 | 输入 | 输出 | 风险 |
|---|---|---|---|---|
| **告警解释**：把 `env_gas_1 超限 66%LEL` 翻成人话 | 高 | 告警字段 + 该测点历史 | 2–3 句解释 + 建议动作 | 可能编造原因 |
| **处置建议**：历史上同类告警怎么处理的 | 中 | 该指标历史告警 + 处置备注 | 候选处置步骤 | 需要足够历史数据 |
| **日报/周报正文**：把报表数字写成一段话 | 高 | `/reports/summary` 的结构化数据 | 一段汇报文字 | 数字必须来自接口，不能让它算 |
| **自然语言查数据**：「上周告警最多的点位」 | 中 | 用户问题 | 转成 API 调用参数 | 要限定在固定查询集内 |
| **视频识别**（跑冒滴漏、仪表读数、人员违规） | **低** | 视频帧 | 检测框 + 置信度 | **文本模型做不了**，要专用视觉模型 + 标注数据 |

## 三、接入原则（写死，不商量）

1. **不碰安全判定**：AI 只做"解释"和"建议"，**不参与告警是否产生的判定**。
   告警阈值、升级、静默这些必须走确定性规则。
2. **数字必须来自接口**：报告里所有统计数字由后端算好再喂给模型，
   不允许模型自己推算或四舍五入。
3. **必须能溯源**：每条 AI 输出后面标注"基于哪几条数据生成"，点得开。
4. **挂了不影响主流程**：模型超时/不可用时，页面照常用，只是"AI 建议"那块显示不可用。
5. **审计留痕**：谁在什么时候让 AI 生成了什么，进 `operation_log`。

## 四、如果要做，最小落地形态

```
后端  POST /ai/explain  {alarm_id}
      - 取告警 + 该指标近 7 天同类告警 + 处置备注
      - 拼 prompt（system 里写死"不确定就说不确定"）
      - 调本机 vLLM/Ollama（Qwen3-32B），超时 8s
      - 结果缓存 30 分钟，写审计
前端  告警详情里一个「AI 解释」按钮，点了显示，带"仅供参考"标记
```

**工作量**：后端 0.5 天 + 前端 0.5 天 + 部署（模型服务 1 天）。
**前置条件**：真机跑起来、告警量攒够 100 条以上（不然没料可喂）。

## 五、为什么不现在做

- 现在告警只有 3 类平台推导项，样本少，模型给不出有价值的解释
- 模型服务本身要占 GPU/内存，8.40 是共享机（已跑 52 个容器）
- 客户合同里没有 AI 项，做了也是白送，出问题还要担责

**真要上，二期单独报价、单独验收。**
