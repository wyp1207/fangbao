# 菜单结构评审提示词（豆包 / GLM）

> 目标：把参考系统的"顶部模块 + 下拉二级菜单"落到我们这一期能兑现的范围里，不要出现点进去是空壳的菜单。

你是做过工业监控/巡检平台信息架构的产品设计者。下面是我们平台的实际情况和参考系统的菜单。请给出**最终的菜单树**，并明确指出哪些菜单项这一期不能放。

规则：
- 直接给结论，不要客套，不要"建议进一步调研"；
- 每条菜单项标注【有数据可做】/【占位，说明未接入原因】/【这一期不要放】；
- 二级菜单最多 5 项，一级菜单最多 6 个；
- 菜单名用 2–6 个汉字，和参考系统保持同一套语言习惯；
- 如果你认为某个参考菜单必须砍，直接说砍掉，并说砍了会失去什么。

## 一、我们的实际情况（已定稿，不可更改）

**机器人**：单台轮式防爆巡检机器人，JCROB 导航系统，HTTP 3546 `/api/v1` + WebSocket 3547。
机器人自己做 SLAM、定位、路径规划、避障。真机 **2026-11-10** 才到现场，交付 **2026-12-01**。

**真实可用的数据（现在就能做）**：
- 实时状态：位姿 x/y/angle、电量、导航状态、急停按钮 driver_port、当前任务、速度/角速度/电压
- 地图：地图列表、当前地图、地图 PNG 切片、巡检点 nav_points（读）
- 任务：任务列表（读）、任务详情、动作序列
- 告警：电量低 / 急停 / 通信中断（平台侧规则），确认动作
- 系统：能力探测 probe、健康检查、用户与角色（已做）

**明确没有的（这一期做不了）**：
- 视频：机器人没有 RTSP 流，云台型号未定 → 只能做占位框
- 环境传感（气体/温湿度/噪声）：设备未定，WebSocket 通道未接 → 只能显示"未接入"
- AI 识别（人脸/仪表/液位）：不在本合同
- 多机器人/多场站：只有一台，场站字段是占位
- 写操作（下发任务/启停/云台/写点位）：要等真机联调 + 现场授权签字，**全部锁着**
- 历史数据/报表：W5 才落库，现在没有历史表
- 充电管理、License、报表数据源、远程连接：不在本期

**当前已实现的页面**：
驾驶舱、地图与点位、任务与巡航（只读+筛选+详情）、告警（列表+确认+规则）、数据查询（任务/告警+CSV）、系统设置（能力探测/运行状态）、用户管理。
