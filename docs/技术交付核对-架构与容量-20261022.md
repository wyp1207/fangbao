# 技术交付核对（架构 / 容量 / 等保）

> 由技术交付视角对 PPT V2.1 与代码做的独立走查（2026-10-22，基线 02d88e4）。
> 结论用于排期与对外口径，不是验收依据。

## 一句话结论

- 按一期合同（单台 JCROB 轮式、只读 + 告警 + 录像 + 报表 + 私有化）：能上线，但容量、多机、断网三类问题要先修。
- 按 PPT V2.1 原样：不能签收。AI 算力层、边缘网关、四足/挂轨/APP、六类算法、3D、区块链、等保三级、GB28181/OPC UA/EHS 均无落地代码。
- 根因：PPT 卖的是 MTHC-AI-XJ* 四类硬件，代码只对 JCROB 轮式 HTTP 3546/3547。

## 五个关键问答（摘要）

1. 边缘网关断网续传：没有。最小补录集 5-7 人天；真边缘网关 25-40 人天。
2. 等保三级：差双因子、密码策略、审计防篡改、日志 180 天、TLS、三权分立等 6 项，工程 15-20 人天 + 测评 1-2 个月。
3. 对外集成：无 API Key、无文档发布、无限流、Webhook 无签名无重试。最小 10-14 人天。
4. 算法口子：能拉 RTSP，不能供流、不能收结果；POST /ai/results 不存在。8-12 人天可打通接入。
5. 50 路视频：1 年 192-385 TB，远超本机 1.9 TB；录像硬上限 2 路、转码 CPU 1.5 核。必须 NVR/对象存储/事件录像。

## 对外口径建议

- 不要签：等保三级“已满足”、区块链存证、表计 98%、定位 5cm、50 路 7×24、六类算法已交付、GB28181/DCS/EHS 已对接。
- 可以签：私有化部署、单台轮式只读接入、告警闭环、多通道通知、录像（2 路/事件）、地图点位、报表导出、审计（基础）、备份脚本。
- 讲标前出三份材料：承诺-实现对照表、50 路视频存储方案、等保差距清单与整改报价。
