# 角色 1：客户方领导（非技术，来看验收演示）

## 第一眼印象

界面看起来功能很全，大屏、地图、视频、告警、设备管理都摆出来了，演示时会比较“像一个平台”。  
但我会很快注意到不少窗口还是占位，环境数据、任务日历、AI 识别这些没有真正跑起来。  
整体更像“单台机器人的监控后台原型”，还不像一个可以支撑厂区安全生产管理的成熟平台。

## 不专业 / 不放心的地方

1. **“看起来有，实际上没有”的模块偏多。**  
   热红外、环境数据、任务日历、系统日志、运行数据等是占位；如果验收时点开发现没数据，会直接影响信任感。

2. **核心写操作被锁定，无法现场验证闭环。**  
   现在只能看任务、看点位、看告警，不能演示“新建任务—机器人执行—异常告警—视频复核—处置留痕”的完整流程。

3. **和成熟巡检平台相比，缺少管理层关心的东西。**  
   对照海康威视机器人巡检平台、大华智慧巡检或亿嘉和声、申昊科技这类成熟机器人巡检产品，行业方案通常会强调任务闭环、缺陷识别、趋势分析、报表统计、多机位/多机器人管理；我们目前大多没有或不完整。  
   注：不同版本功能不确定，但这些厂商公开方案通常包含设备状态监测、巡检任务管理、告警/缺陷管理、视频联动和统计分析。

4. **AI 识别和红外诊断缺失，会显得“机器人价值”没释放。**  
   客户买巡检机器人，通常不只是看画面，还希望发现仪表读数异常、跑冒滴漏、温度异常、人员违规等；目前明确没有 AI 识别，热红外也只是占位。

5. **录像当前暂停落盘，事故追溯能力不足。**  
   如果领导问“上周三凌晨报警时的视频能不能调出来”，当前平台可能给不出确定答案，这在安全生产场景里是硬伤。

6. **消息中心内存保存、重启清空，不适合作为正式交付能力展示。**  
   这会让人担心系统重启后告警、通知、操作痕迹丢失，正式项目里显得不够可靠。

## 如果只能改三件事

1. **把所有占位模块要么隐藏/标注“规划中”，要么尽快接入真实数据，避免演示时露出空页面。**
2. **打通一条可演示的业务闭环：创建或选择巡检任务、机器人执行、产生告警、自动关联视频、人工确认并留痕。**
3. **补齐管理层看板和报表：巡检完成率、告警数量、确认率、设备在线率、异常趋势，并支持导出/打印。**

# 角色 2：普通观众（第一次打开这个网页的人）

## 第一眼印象

首页信息很多，顶部状态栏、视频窗口、地图、告警环图、消息、点位列表都在，第一眼会觉得“挺酷、挺复杂”。  
地图上能看到机器人位置和轨迹，这可能是最吸引人的部分。  
但如果没有说明，我可能不知道哪些按钮能点、哪些只是展示，尤其是控制操作还被锁定。

## 不专业 / 不放心的地方

1. **信息密度高，但新手引导不足。**  
   云台、车体、SLAM 地图、位姿、轨迹、点位、充电房等术语对普通用户不友好，不知道每个区域代表什么。

2. **视频窗口和环境数据如果是黑屏或占位，会让人误以为系统坏了。**  
   普通用户不会区分“未接入”“无权限”“设备离线”“组件加载失败”，需要明显状态提示。

3. **控制面板有摇杆但写操作锁定，容易让人困惑。**  
   用户可能会尝试拖动摇杆，发现没反应；建议直接显示“只读模式/无控制权限/需双人授权”，而不是简单失效。

4. **告警环图如果没有解释，不知道严重程度和含义。**  
   普通用户更关心“出了什么事、在哪里、严不严重、该怎么办”，而不是只看一个环形统计。

5. **实时消息如果滚动很快、重启后又清空，会让人抓不住重点。**  
   对照 **Frigate** 这类开源视频 NVR/事件项目，它会把检测事件、录像片段、时间线和摄像头关联起来；普通用户能回看“什么时候、哪个摄像头、发生了什么”。我们现在消息更像临时通知。

6. **功能入口多，但缺少“我现在能做什么”的主路径。**  
   例如应该突出三个入口：看实时机器人、查今天巡检任务、处理未确认告警；现在菜单更像按系统模块堆给管理员看。

## 如果只能改三件事

1. **给首页增加新手说明和空状态文案，明确“真实数据、占位、离线、无权限”的区别。**
2. **把锁定的摇杆和控制面板改成清楚的只读/无权限提示，避免用户误以为卡死或故障。**
3. **把“告警—位置—视频—消息”串起来，点击告警能直接跳到地图位置和相关视频/任务上下文。**

# 角色 3：专业工业运维人员（化工 / 石化厂仪表或安防主管）

## 第一眼印象

作为单台防爆巡检机器人的运行监控平台，实时地图、go2rtc 低延时视频、RTSP 摄像头管理、告警确认和 CSV 导出已经具备基础雏形。  
但放在化工/石化安全生产场景，目前更像演示系统或单机版运维后台，离生产准入和长期可靠运行还有明显差距。  
最大问题不是页面，而是可信数据、历史追溯、权限审计、外部对接和断网离线能力不足。

## 不专业 / 不放心的地方

1. **告警可信度不足，缺少阈值依据、告警分级、联动复核和误报漏报管理。**  
   现在告警规则阈值只读，且没有 AI、环境采集、红外诊断，也没有告警与摄像头/任务关联。运维人员无法判断告警是真实工艺异常、设备故障、机器人误报，还是网络抖动造成的假告警。

2. **历史数据库和审计能力缺口很大。**  
   资料说明历史数据库在 W5，系统日志占位，消息还在内存里且重启清空。化工场景要求事后追溯：谁在什么时候确认了告警、谁修改了阈值、谁控制过机器人、机器人当时在哪里、视频是什么、任务执行到哪一步，这些现在不能完整闭环。

3. **权限模型看起来偏简单，不能满足高危操作管控。**  
   用户管理有 CRUD/角色/重置密码，但没看到细粒度 RBAC、双人复核、操作审批、控制令牌、会话超时、指令鉴权、防爆区域操作边界等。机器人云台/车体控制属于高风险动作，应当区分查看员、值班员、运维工程师、安全管理员和审计员。

4. **视频不落盘，告警又不联动摄像头，事故复盘能力不足。**  
   当前录像计划“暂停落盘”，而告警没有和摄像头/任务关联。即使 go2rtc MSE 延时约 0.5 秒适合实时看，也不能替代事件前后录像留存。对照 **Frigate**，其开源方案至少围绕摄像头事件组织录像和时间线；商用平台通常还会做告警弹窗、弹屏、录像定位、证据链导出。

5. **断电、断网、服务器重启、机器人离线时的策略没有体现。**  
   内网部署本身可以接受，但需要说明：机器人失联是否自动返航/就近停车/继续执行本地任务，服务器重启后消息和任务状态如何恢复，网络恢复后是否断点续传，SQLite/PostgreSQL 是否定时备份，go2rtc/ffmpeg 异常是否自动拉起。

6. **与厂区现有系统和监管平台对接能力不足。**  
   没看到 DCS、SIS、视频平台、门禁、可燃有毒气体系统、消防报警、统一身份认证、应急管理局平台接口。安全生产场景通常要求与“工业互联网+危化安全生产”、双重预防机制、重大危险源监控等体系对接；具体地方平台接口各省不同，但通常会涉及组织、风险分区、隐患、巡检、报警、视频和统计上报。具体接口规范需按属地应急管理部门要求确认，不能假定已满足。

## 如果只能改三件事

1. **先补可信告警闭环：告警分级、阈值版本、持续时间/防抖、确认/处置流程、告警时机器人位置、任务、摄像头和前后录像自动关联。**
2. **建立历史库和审计追溯：持久化告警、任务、遥测、视频索引、用户登录、控制指令、规则修改和确认记录，确保重启不丢、可按事件导出证据链。**
3. **按工业上线标准补可靠性与对接：细粒度权限/审批、断网离线策略、服务守护和备份恢复，并预留标准 API 对接 DCS/SIS、视频平台、LDAP/AD、统一安防平台及监管上报系统。**

# 对照材料引用

以下对照只引用公开层面的常见能力；不同版本、项目和部署配置会有差异。

1. **海康威视 / 海康机器人巡检平台类方案**  
   行业常见能力包括多设备接入、视频监控、巡检任务、告警中心、报表统计、视频联动、设备运维，部分方案支持 AI 识别、热成像测温、环境量接入和平台级联网。  
   我们的差距：单机器人管理、AI 缺失、红外占位、视频告警不联动、无成熟报表和多机调度。

2. **大华股份 / 大华巡检与智慧安防平台类方案**  
   成熟安防平台通常具备视频预览回放、告警联动、电子地图、设备管理、权限管理、操作日志、录像存储策略和级联对接能力。  
   我们的差距：录像暂停落盘、告警与摄像头无关联、系统日志占位、权限粒度和外部级联能力不明。

3. **亿嘉和、申昊科技、国自机器人、优艾智合等巡检机器人产品**  
   这类成熟产品通常不只提供远程遥控，还围绕行业巡检任务提供自动巡检、点位管理、仪表/设备识别、异常告警、数据报表、多任务或多机器人管理能力；不同行业版本能力不确定。  
   我们的差距：任务不能下发、点位不能编辑、AI 识别缺失、多机器人调度缺失、历史趋势和专业报表不足。

4. **应急管理部推动的“工业互联网+危化安全生产”、双重预防机制数字化、重大危险源监测预警相关平台**  
   公开政策方向通常强调风险分级管控、隐患排查治理、重大危险源监测、报警处置、人员定位、视频监控、特殊作业、应急管理和数据上报。各地平台接口和验收细则不同，需按属地要求确认。  
   我们的差距：偏单机监控，没有看到风险/隐患流程、监管上报、处置闭环、DCS/气体/消防等系统数据融合。

5. **ThingsBoard（开源 IoT 平台）**  
   有设备资产管理、遥测数据接入、规则引擎、告警生命周期、仪表板、RPC 控制、多租户/权限和多种协议接入。  
   我们的差距：缺少规则引擎、设备遥测历史、告警状态机、多协议接入和成熟租户/权限体系。

6. **Frigate（开源 NVR + 物体检测项目）**  
   以摄像头为中心，提供事件检测、录像、时间线、片段检索和 Home Assistant 等集成；具体功能随版本变化。  
   我们的差距：go2rtc 解决了实时流，但事件化录像、告警片段、摄像头时间线和证据检索不足。

7. **FUXA（开源 SCADA/HMI 项目）**  
   面向工业现场可视化，支持设备通信、变量、组态画面、报警、数据记录等工业界面能力；具体驱动支持随版本确认。  
   我们的差距：页面更偏 Web 后台，没有看到 Modbus、OPC UA 等工业协议接入和工艺变量组态能力。

8. **Grafana + InfluxDB 时序数据组合**  
   常见做法是用 InfluxDB 存储传感器、设备状态、环境量等时序数据，用 Grafana 做趋势曲线、仪表盘、告警和历史分析。  
   我们的差距：环境传感未接入，运行数据占位，历史数据库未完成，无法支撑长期趋势分析和故障诊断。

# 总体结论

这个平台当前最适合被定义为：**“单台防爆巡检机器人的实时监控与基础管理后台”**。  
它的优势是实时视频、地图位姿、摄像头管理、告警列表和基础后台已经成型；但如果按化工厂正式安全生产平台验收，短板集中在 **数据可信、历史追溯、视频证据、权限审计、离线可靠性、外部系统对接**。

优先级建议不要先做 3D 或大屏美化，而是按以下顺序：

1. **告警闭环 + 视频联动 + 事件录像**
2. **历史数据库 + 操作审计 + 证据链导出**
3. **任务写操作闭环 + 权限审批 + 离线/恢复策略**
4. **环境/红外/DCS 等真实数据接入**
5. **报表、监管接口和多设备能力扩展**

## 智谱 GLM（glm-5.2）

### 角色 1：客户方领导（非技术，来看验收演示）

**第一眼印象**
1. 大屏看着挺唬人，有地图有视频有时钟状态带，第一眼像个正经系统。
2. 但只要多盯一会儿就能发现，画面上好多“占位”字样，环境数据、录像计划、任务日历全是空壳子，像买了个半成品。
3. 跟隔壁厂用的海康或华为平台一比，缺了智能 AI 识别和 3D 数字孪生，演示时拿不出手。

**哪些地方会让我觉得不专业/不放心**
- 到处是“占位”：环境监测占位、任务日历占位、运行数据占位，验收时会被同行或上级一眼看穿，显得预算没花到位。
- 录像居然“暂停落盘”：防爆巡检机器人的核心就是取证，连录像都存不下来，出了安全事故谁担责？
- 不能下发任务和编辑点位（写操作锁定）：这等于买了个只能看不能用的摆设，业务部门没法自主排班。
- 告警不能关联视频和任务：光弹个告警消息，看不到是哪个点位、哪路视频触发的，没法做事故复盘。
- 告警和消息重启就没了：内存存的消息，服务器一重启全丢，这算哪门子管理系统？
- 跟大厂比缺了“面子功能”：没有 3D 站区漫游，没有 AI 火情/跑冒滴漏识别，向上级汇报时缺乏亮点。

**如果只能改三件事，改哪三件**
1. 恢复录像落盘并实现告警与视频片段的绑定，确保出事有据可查。
2. 联调打通写操作授权，让业务人员能自己建任务、下派单，变成真业务系统。
3. 把首页所有“占位”UI隐藏或换成静态图，别让验收的人看到“半成品”字样。

### 角色 2：普通观众（第一次打开这个网页的人）

**第一眼印象**
1. 界面排版挺紧凑，左边地图右边视频，中间还有个摇杆，有点像玩无人机或打游戏的感觉。
2. 视频画面挺流畅，点摇杆基本没延迟，地图上还有个小车在跑并拖着尾巴，挺直观。
3. 但是顶部和列表里好多看不懂的英文（比如 go2rtc MSE、RTSP CRUD），而且不少地方写着“未接入”，让人觉得是不是坏了。

**哪些地方会让我觉得不专业/不放心**
- 摇杆没有死区保护或力度提示，不小心点一下车可能就撞了，写操作锁定解开后挺危险的。
- 很多页面是只能看不能点的（只读），点了一圈发现啥都改不了，体验有点憋屈。
- 地图是黑白马赛克（SLAM栅格图），对不懂的人来看像是一堆乱码，不如卫星地图或3D模型好懂。
- 告警统计环图看着好看，但点进去发现告警记录没法跟视频联动，不知道到底哪里报警了。
- 摄像头管理里写着“RTSP CRUD”这种程序员才懂的词，普通用户根本不知道这是干嘛的。
- 视频回放页面如果能正常用还行，但看到“录像暂停落盘”，那回放里到底有没有东西看？

**如果只能改三件事，改哪三件**
1. 给云台和车体摇杆加上明显的“安全限速”和“松手即停”视觉反馈。
2. 把界面上的技术黑话（如 RTSP、go2rtc）改成“添加视频流”这种人话。
3. 在 SLAM 栅格图上叠加厂区实际背景照片或简单的区块标注，让人能看懂车在哪栋楼。

### 角色 3：专业工业运维人员（化工/石化厂仪表或安防主管）

**第一眼印象**
1. 架构很轻量（Vue3+FastAPI+Docker），部署确实快，但单机 SQLite 和单开发者让我对它的工业级高可用性极度存疑。
2. 视频流用 go2rtc 走 MSE 延迟 0.5s 是个亮点，但在防爆区如果没有环境数据接入和硬安全联动，也就是个高级遥控玩具。
3. 断网断电、审计追溯、数据留存这块基本是裸奔状态，根本过不了厂里安环部的验收。

**哪些地方会让我觉得不专业/不放心**
- 无历史数据库与本地持久化：消息在内存里、录像暂停落盘、告警阈值只读，这在化工厂是致命的，出了事故没法追溯责任。
- 缺乏工业级冗余与断网策略：单台 nginx+单容器，如果内网波动或断电，机器人不仅失控，连现状都看不到，没有边缘端保活。
- 权限与审计粒度太粗：只有基本的账号 CRUD，没有三权分立（操作员/管理员/审计员），没有操作防抵赖日志，不符合等保2.0要求。
- 无法对接厂区现有系统：没看到 OPC UA / Modbus 接口去对接 DCS，也没有国标 GB28181 去对接厂区集中视频平台，是个纯信息孤岛。
- 告警闭环缺失：告警不能联动摄像头预置位，没有短信/电话/企业微信上报机制，夜班没人盯着大屏就等于没告警。
- 缺少应急管理局要求的上报能力：危化企业要求“工业互联网+危化安全生产”数据上报，这里连基础的人员定位和设备运行状态都存不下来，更别提对接省厅平台了。

**如果只能改三件事，改哪三件**
1. 立即启用 PostgreSQL 历史数据落盘，并完善系统操作日志（谁在几点动了摇杆），满足最基本的事故追溯要求。
2. 恢复录像落盘并实现告警抓拍/录像片段自动关联，确保每个报警有图有真相。
3. 给机器人系统加一套 GB28181 视频推送和标准 OPC UA 数据接口，保证能接入厂区现有安防/DCS总控平台。

### 对照材料引用与差距分析

1. **海康威视/大华 行业级巡检管理平台**
   - **它们有什么我们没有**：完善的“视频告警联动”（报警后自动弹窗预置位抓拍）、AI 算法（火焰/烟雾/跑冒滴漏识别）、基于角色的权限管控体系。
2. **优艾智合/亿嘉和 轮式巡检机器人系统**
   - **它们有什么我们没有**：多机协同调度系统（ ours 明确没有）、数字孪生 3D 站区展示、完善的巡检报表自动生成（CSV 导出太简陋，人家是标准工业报表）。
3. **“工业互联网+危化安全生产”省级监管平台**
   - **它们有什么我们没有**：强制要求的双重预防机制上报模块、人员定位轨迹留存、设备运行历史数据 90 天/180 天不可篡改留存。
4. **开源项目 ThingsBoard / Grafana+InfluxDB**
   - **它们有什么我们没有**：时序数据库支持的海量遥测数据存储、灵活的仪表盘与数据可视化规则引擎。

### 四、平台与工业标准差距表

| 能力 | 行业常见做法 | 我们现在 | 差距等级 | 补的成本（人日） |
| :--- | :--- | :--- | :---: | :---: |
| **告警可信度** | 告警自动关联视频预置位抓拍，多级上报 | 纯文本消息在内存，重启丢失，无视频关联 | 大 | 5-7 |
| **历史与追溯** | 时序数据库(如InfluxDB)存半年以上，不可篡改 | 无历史数据库(W5)，消息不落盘，录像暂停 | 大 | 5-10 |
| **权限与审计** | 三权分立，操作日志持久化，符合等保 | 仅账号CRUD/重置密码，无操作行为审计日志 | 中 | 3-5 |
| **视频与告警联动** | 告警触发自动弹窗、抓图、存段录像 | 视频流仅支持go2rtc直播，无联动逻辑 | 大 | 4-7 |
| **断网/离线策略** | 边缘端保活，断网本地缓盘，恢复续传 | 无边缘策略，断网即失联，单容器单点故障 | 中 | 10+ |
| **外部系统对接** | GB28181入视频平台，OPC UA/Modbus入DCS | 信息孤岛，仅支持内网网页访问 | 大 | 7-15 |
| **多设备接入** | 统一调度多机型，甚至异构机器人 | 明确不支持，单机运行 | 中 | 10+ |
| **报表与上报** | 自动生成日/周报，对接应急局/省级安全平台 | 仅支持基础CSV导出，无标准报表及监管上报 | 大 | 5-10 |
