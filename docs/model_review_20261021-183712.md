# 工业巡检平台「按钮功能性」审计与换场地/导入地图设计方案

## 一、第一部分：按钮「应该做什么」的判定标准

### 1. 三类按钮的判定规则与示例

#### （1）必须实现的按钮
**判定标准**：按钮对应业务流程闭环所需的核心操作，且后端接口、数据权限、异常处理链路已完整就绪，点击后能产生可验证的实际业务效果。
- 示例1：告警中心的「导出」按钮——已对接告警数据库，可真实生成并下载符合筛选条件的CSV文件，满足用户数据留存需求。
- 示例2：设备管理的「测试连接」按钮——已实现TCP/HTTP探测逻辑，可真实反馈设备在线状态与协议连通性，支撑设备台账有效性验证。

#### （2）必须禁用并说明的按钮
**判定标准**：按钮对应操作属于规划内业务能力，但依赖未就绪的核心资源（如硬件联调、授权资质、配套数据），且操作触发后会产生用户预期外的无效行为或数据风险。
- 示例1：巡检点位的「同步到机器人」按钮——依赖真机控制接口联调与现场操作授权，禁用时通过title明确提示「需完成真机联调及现场授权后开放」。
- 示例2：任务管理的「下发」按钮——依赖机器人任务执行协议与安全校验机制，禁用时标注「待真机联调完成，当前仅支持任务查看」。

#### （3）应该直接删掉的按钮
**判定标准**：按钮对应功能无明确业务场景支撑、与当前产品定位无关，或永久无法实现且无替代方案，长期存在只会误导用户操作。
- 示例1：若平台已确定不支持第三方热红外设备接入，首页的「热红外窗口」跳转按钮（无实际设备与数据流支撑）应直接删除，而非保留占位。
- 示例2：若场站管理模块短期无多场站拓展规划，首页的「场站下拉」选择组件（仅存单条假数据）应直接移除，避免展示非真实数据。

### 2. 「写操作弹未开放说明」的验收评价
**结论：合格但偏保守，领导验收时属于「不减分但难加分」的选项，处理不当会小幅减分。**
- 合理性：该做法明确告知用户操作限制，未伪造执行结果，符合工业系统「不误导、不盲动」的基础要求，避免了无效请求与安全隐患，比按钮无响应或报错更友好。
- 验收风险：若弹窗仅笼统提示「写操作未开放」，未说明限制原因、预计开放节点、替代方案（如「当前仅支持平台侧点位预览，真机同步需待2026-11-15联调完成」），领导会感知为功能完成度不足，属于「交差式」实现，而非「交付级」设计。
- 优化方向：弹窗需补充「当前阶段定位+限制原因+替代操作+开放条件」四要素，例如：「当前为平台模拟验收阶段，任务下发需真机安全校验与现场授权，您可先通过「详情」查看任务配置，联调完成后自动开放该能力」。

## 二、第二部分：换场地/导入地图完整设计方案

### 1. 三类地图数据源的接入方式
| 数据源类型 | 接入流程 | 核心处理环节 |
|------------|----------|--------------|
| 机器人自主扫描建图 | 1. 机器人现场完成SLAM建图，生成栅格地图包（含PNG栅格图、YAML坐标配置、点云数据）；2. 通过机器人端运维接口将地图包上传至平台边缘网关；3. 平台自动解析配置并生成地图草稿；4. 现场工程师校准点位、相机标定后提交发布 | 地图格式校验、SLAM坐标与平台坐标对齐、点位自动关联、导航有效性预校验 |
| 客户提供CAD图纸 | 1. 客户提供DWG/DXF格式的二维平面图纸，标注比例尺、楼层、正北方向、设备点位；2. 平台通过CAD解析工具提取墙体、通道、障碍物图层，转换为标准栅格PNG；3. 运维人员手动校准原点、分辨率，标记禁行区与巡检点；4. 同步至机器人进行路径可行性验证（真机阶段） | 图层过滤、比例尺校准、障碍物矢量化、坐标原点人工锚定 |
| 现场测绘数据 | 1. 测绘人员提供带绝对坐标（WGS84/UTM）的点位表、区域轮廓矢量文件（SHP/GeoJSON）；2. 平台导入矢量数据，渲染生成栅格地图底图；3. 叠加现场标记的设备、通道、巡检点；4. 机器人现场补扫修正障碍物与可通行区域 | 坐标投影转换、矢量转栅格、现场点位匹配、地图精度校验 |

| map_status | tinyint | 是 | 状态：0-草稿 1-已发布 2-已停用 |
| resolution | decimal(10,4) | 是 | 地图分辨率（米/像素） |
| origin_x | decimal(12,4) | 是 | 地图原点X坐标（机器人坐标系，米） |
| origin_y | decimal(12,4) | 是 | 地图原点Y坐标（机器人坐标系，米） |

#### （2）地图扩展关联表（配套最小存储）
- `map_nav_point`：map_id、point_id、点名称、x/y坐标、朝向、点类型（巡检点/充电桩/待命点）
- `map_camera`：map_id、camera_id、相机名称、安装位置x/y、俯仰角、视场角、关联设备ID
- `map_robot_rel`：map_id、robot_id、robot_map_hash（机器人端地图唯一标识）、sync_status、last_sync_time

### 3. UI入口、操作步骤与失败提示
#### （1）入口位置
放在「地图监控」模块顶部，与「刷新地图列表」并列，按钮名称为「导入地图」，按角色权限控制显示（仅运维管理员可见）。

#### （2）四步操作流程
1. **选择数据源与上传文件**：选择「机器人扫描图/CAD图纸/测绘文件」类型，上传对应格式文件，勾选所属场站与楼层；
2. **参数校准与预览**：系统自动解析分辨率、原点，人工修正比例尺、正北方向、原点位置，在预览页标记禁行区、核心通道；
3. **关联信息配置**：绑定对应机器人，批量导入/勾选巡检点、相机位置，配置地图生效范围；
4. **校验与提交**：平台完成格式、坐标、点位完整性校验，生成草稿，真机阶段补做路径验证后可发布。

#### （3）失败提示规则
- 文件格式错误：直接在上传页红字提示「仅支持DWG 2018及以下版本DXF文件，请转换后重新上传」，并提供格式转换工具下载链接；
- 解析失败：提示「图纸缺少比例尺图层，请补充标注1米参考长度后重试」，高亮缺失的图层/字段；
- 坐标校准失败：预览页标红偏差超过阈值的点位，提示「3个巡检点坐标偏差超0.5米，请重新锚定原点或核对点位表」；
- 机器人匹配失败（真机阶段）：提示「当前机器人未识别该地图包，请确认地图已上传至机器人控制器，设备端hash为XXX，平台解析hash为XXX」。

### 4. 导入地图与机器人自带地图的对应规则
1. **唯一标识绑定**：机器人扫描生成的地图自带唯一hash值，平台导入时自动提取并写入`map_robot_rel`表，作为双向匹配的核心依据，不依赖同名匹配；
2. **双坐标系兼容**：平台同时存储机器人相对坐标系（用于导航控制）与场地绝对坐标系（用于多楼层/多场地拼接），导入CAD/测绘图时通过3个以上现场固定参考点（如充电桩、消防栓）完成坐标转换矩阵计算，对齐机器人SLAM坐标系；
3. **同名冲突处理**：若导入地图与机器人端现有地图同名但hash不同，弹窗提示「检测到同名异质地图，请选择：覆盖机器人端地图/新建平台地图并重命名/取消导入」，禁止默认覆盖；
4. **生效范围隔离**：单台机器人仅可绑定1张当前生效地图，历史地图自动标记为「已停用」，平台可查看多版本地图但切换需现场授权。

### 5. 无真机时的可落地项与等待项（零假数据原则）
#### 可提前完成（全真实逻辑与数据）
1. CAD/测绘文件的上传、解析、格式校验模块；
2. 地图数据模型设计、数据库建表、PNG/源文件存储服务；
3. 地图参数人工校准、预览、草稿保存、版本管理功能；
4. 巡检点/相机位置的Excel批量导入、坐标在地图上的真实渲染；
5. 平台侧多地图切换查看、地图列表筛选、详情查看功能；
6. 基于地图坐标的点位距离测算、区域圈选（纯几何计算，不依赖真机）。

#### 必须等待真机联调
1. 机器人扫描地图的自动拉取、远程上传触发；
2. 平台地图向机器人端的下发、同步、覆盖操作；
3. 地图导航可行性校验（路径规划、障碍物冲突检测）；
4. 机器人端地图hash校验、在线状态下的地图切换控制；
5. 点位同步到机器人、导航定位精度验证。
