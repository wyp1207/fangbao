# 请为"防爆巡检机器人平台"设计一份可执行的联调测试方案（并挑我们现状的漏洞）

你是同时干过测试平台建设、机器人软硬件联调和全链路压测的测试架构师。
下面是我们平台的真实情况，以及一份"联调测试平台能力体系"的纲要。请据此产出**能直接照着跑**的方案。

## 平台真实情况（不要假设）
- 后端：FastAPI + SQLAlchemy + MySQL/SQLite，单 uvicorn worker；JWT httpOnly cookie + CSRF 双提交；scrypt；TOTP；审计哈希链
- 前端：Vue3 + Vite + Pinia，无组件库；34 个路由
- 设备：1 台 JCROB 轮式（HTTP 3546 + WS 3547）、1 台云深处 X30（TCP 30000 UDP 43893）、1 台本地模拟器
- 背景循环：设备轮询、环境 WS 接入、保留期清理、遥测聚合、计划调度、通知分发、磁盘监控、工单升级、任务看门狗、传感器网关、巡航线程
- 已有自测：106 个 pytest 用例、UI 冒烟脚本（34 路由）、对抗测试（越权 6 项 + 审计链篡改）、巡航 E2E（模拟器 3 点位）
- 真机：X30 在厂区（192.168.1.106），当前不通；JCROB 真机 192.168.1.100 也不通
- 没有：消息队列、Redis、分布式部署、CI 流水线、HIL 机柜

## 请输出
### 一、测试矩阵（表）
按"六大基础模块 + 五大进阶能力"逐项给出：测什么、怎么测（具体命令/脚本思路）、优先级 P0/P1/P2、
我们的现状（已有/缺失/做不了）、判据（通过标准）。

### 二、10 个最该补的联调用例（具体到接口与断言）
每条给：前置、步骤、断言、失败意味着什么。要能直接用 curl/python 写出来。

### 三、我们这套架构的 5 个"联调必翻车点"
结合单 worker、无 MQ、SQLite/MySQL 双支持、轮询式状态同步、审计哈希链这些事实，
指出在"多模块联调"时最可能出问题的地方，以及怎么用测试提前发现。

### 四、做不了的部分怎么诚实地讲

能覆盖到什么程度？在验收材料里应该怎么表述才不算吹牛？
