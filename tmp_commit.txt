feat(task): A–D 四项落地（下发幂等、能力协商、到点三态、资源锁+定位门）

A 下发幂等
- 迁移 0024：task_run 加 order_id(唯一)、order_update_id、dispatch_state、
  dispatch_attempt、dispatch_lease_until、cancel_requested_at、last_seq；建 resource_lock 表
- 先落库再发网络：条件 UPDATE 抢 pending→sending（SQLite 不支持 FOR UPDATE，条件 UPDATE 两端一致）
- order_id = JC-R{run:06d}-A{attempt:02d}；重复下发 409 ORDER_IN_FLIGHT
- 结果未知（超时/断网）→ 保持 sending + 租约，绝不盲重试
- reconcile_dispatches 每 60 秒对账：租约到期无回执 → failed，有 external_id → sent
- 实测：order_id=JC-R000031-A01、dispatch_state=sent、attempt=1；第二次下发被拦（400 BAD_STATUS）

B 能力协商
- 两个适配器加 capabilities：supports_batch / supports_inline_actions / supports_pause / cancel_semantics
- 全部默认 False = 逐点（行为不变）；真机确认后在适配器改一个布尔，不动巡航逻辑

C 到点三态
- _wait_arrival 返回 arrived / suspect / failed
- 超容差但 ≤ 2.5 倍 → suspect：标 step.status=suspect + 发 loc_suspect 告警，不重试、不算失败
- 实测：0.5m→arrived、1.5m→suspect、4m→failed（用位移而非瞬时速度，避免机器狗踏步误判）

D 资源锁 + 定位门
- resource_lock：进程内锁 + key 字典序（消灭环路等待）+ TTL；DB 表只做快照，不承担互斥
- 巡航到点动作期间占 point:<id>，finally 释放
- 下发前检查 located==false → 409 NOT_LOCALIZED（VDA5050 的 localized 安全门）
